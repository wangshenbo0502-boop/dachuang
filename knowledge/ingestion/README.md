# ingestion/ — 数据摄取流水线

## 目录职责
协调 RAG 的数据预处理全流程（Load → Parse → Split → Index），将原始知识文档转化为可供检索使用的索引。

## 为什么需要
- `loader/`、`parser/`、`splitter/`、`indexes/` 是分散的独立模块
- 需要一个协调层将它们串成完整的数据处理流水线
- 避免在各 Pipeline 中重复写数据加载逻辑

## 当前实现
- `IngestionPipeline`：一次性全量摄取文档

## 未来扩展
- 增量更新（只处理新增/修改的文档）
- 多来源并发摄取
- 断点续传
- 定时调度（按 cron 表达式自动更新索引）
