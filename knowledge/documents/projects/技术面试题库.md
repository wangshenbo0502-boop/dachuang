# 技术面试题库

## 项目概述

做一个刷题平台，用户可以按标签/难度/公司刷题，系统记录完成进度并智能推荐。类似 LeetCode 的简化版。

## 核心功能

- 题库管理（按分类/难度/公司筛选）
- 代码编辑器（在线写代码）
- 用户答题记录与进度
- 基于薄弱点的题目推荐
- 每日一题推送

## 技术收获

- 多对多数据关系建模（题目-标签-用户）
- 基于规则的内容推荐算法
- 进度追踪与数据可视化
- 代码编辑器集成

## 适合人群

想做一个有实际用途项目的同学

## 前置技能

- Vue3
- FastAPI
- MySQL

# 技术难点与面试展开点

题库项目的价值在**数据建模与检索设计**，而非简单 CRUD。**数据模型**：题目表（题面/难度/标签/来源）、标签多对多、题目关联（相似题推荐——图关系）、用户做题记录表（状态：未做/通过/重做中）与提交记录表（时间/内存/语言）。如何设计"相似题目推荐"（多对多关系 + 权重）与"每日一题"调度（定时任务 + 去重）是建模深度的体现。

**检索与聚合**：按标签/难度/关键词的复合筛选（MySQL 索引设计 or 接入 ES 的分词搜索）、做题统计聚合（连续打卡天数——SQL 窗口函数或 Redis Bitmap，两种方案对比是亮点）、热门题目榜单（Redis ZSet 排行榜）。

**判题系统**（可选进阶）是最强区分度模块：沙箱执行（Docker 隔离运行用户代码，资源与网络限制）、判题流程（编译→运行→对比输出）、安全防护（防死循环——超时、防炸内存、防读写文件）。哪怕只做简化版，"我了解 LeetCode 判题沙箱怎么做"在面试中就是话题主导权。

**面试高频**：表结构设计与索引、连续 N 天打卡的 SQL/Redis 实现、排行榜 ZSet 原理、如何安全执行用户提交的代码（沙箱与资源限制）、相似题推荐的图遍历。

# 项目演进路线与推荐资源

**演进路线**：基础版（题目表 + 标签筛选 + 做题记录）→ 进阶版（相似题推荐、连续打卡统计、ZSet 排行榜）→ 完整版（Docker 沙箱判题简化版：超时与资源限制 + 题解社区功能）。判题模块哪怕简化实现，也建议在 README 中写清安全设计（隔离、限额、超时），这是面试的天然深水区话题。

**推荐资源**：LeetCode API 与题库结构参考；Redis 官方文档（Bitmap 与 ZSet）；Docker 官方文档（资源限制参数 cgroup/memory）；Firecracker 与 judge0 等开源判题沙箱（架构参考）。
