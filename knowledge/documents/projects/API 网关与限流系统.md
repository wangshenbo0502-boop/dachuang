# API 网关与限流系统

## 项目概述

自建一个简易 API 网关，实现路由转发、限流、熔断功能。理解微服务基础设施的核心原理。

## 核心功能

- 动态路由配置
- 令牌桶限流算法
- IP 黑白名单
- 熔断降级
- 请求日志和统计

## 技术收获

- 令牌桶/漏桶限流算法
- 网关在微服务架构中的定位
- Redis 实现分布式限流
- 熔断器模式

## 适合人群

想深入后端基础设施的同学

## 前置技能

- Java
- Redis
- HTTP协议理解

# 技术难点与面试展开点

**限流算法**是这个项目的灵魂，必须四种都能手写或画图讲清：① 计数器（固定窗口——临界突刺问题）；② 滑动窗口（细分小窗口平滑统计）；③ 漏桶（恒定速率放行，削峰填谷）；④ **令牌桶**（恒速发牌、允许突发，Guava RateLimiter 与 Sentinel 的基础算法）。分布式场景下单一进程限流失效，需用 Redis + Lua 脚本实现原子化的集群限流——"为什么必须用 Lua"（检查与扣减的原子性）是高频追问。

**网关的职责链**是系统设计能力的展示面：路由转发（路径/头信息匹配）、认证鉴权（JWT 校验、签名验证）、黑白名单、请求日志与链路追踪（traceId 注入）、协议适配。可对比 Nginx/OpenResty、Spring Cloud Gateway、Kong 的选型差异（性能 vs 生态 vs 可编程性）。

**高可用设计**：网关自身不能成为单点——无状态水平扩展 + 注册中心动态感知下游服务、下游故障时的熔断降级与超时重试策略、热 key 的本地缓存。面试高频：四种限流算法对比、令牌桶与漏桶区别、Redis+Lua 限流的实现细节、JWT 无状态鉴权与 Session 有状态鉴权的取舍、网关挂了怎么办。

# 项目演进路线与推荐资源

**演进路线**：基础版（Spring Cloud Gateway/自研过滤器 + 本地令牌桶）→ 进阶版（Redis+Lua 分布式限流、JWT 鉴权、路由动态配置）→ 完整版（Sentinel 集成、熔断降级、压测报告：单机 QPS 与限流精度数据）。压测数据（JMeter/wrk）是简历量化的关键，务必实测而非估算。

**推荐资源**：Sentinel 官方 Wiki（限流规则与滑动窗口实现）；Guava RateLimiter 源码（令牌桶标准实现）；Redis 官方文档（Lua 脚本与原子性）；Spring Cloud Gateway 官方文档（过滤器链设计）。
