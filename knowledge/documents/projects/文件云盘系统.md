# 文件云盘系统

## 项目概述

仿百度网盘的文件管理系统。大文件分片上传和秒传是后端面试中非常加分的项目经验。

## 核心功能

- 文件/文件夹管理（新建/重命名/删除/移动）
- 大文件分片上传 + 断点续传
- 文件秒传（Hash去重）
- 文件分享链接（带密码+有效期）
- 回收站（30天恢复）

## 技术收获

- 大文件分片上传原理
- 文件 Hash（MD5/SHA256）去重
- 断点续传实现
- 对象存储（OSS/S3）集成

有一定项目经验、想在简历中增加亮点的同学

## 前置技能

- 前后端框架基础
- MySQL
- 文件操作基础

# 技术难点与面试展开点

云盘项目的三大技术富矿：**大文件上传、存储设计、秒传与分块**。

**大文件上传**：分片上传（前端切片 → 并发上传 → 服务端合并，断点续传依赖分片状态记录）、上传进度与失败重试、并发控制的浏览器连接数限制。File API（Blob.slice）与 FormData 的运用是前端基本功；后端的合并原子性与完整性校验（MD5/SHA-256）是工程严谨性的体现。

**秒传与去重**：文件哈希（前端抽样哈希 + 全量哈希的权衡——大文件全量 MD5 计算耗时的优化：首尾分片采样）→ 命中已存在文件则仅建立引用记录（引用计数），删除时的引用处理与物理/逻辑删除策略。这是"用数据结构思想优化真实系统"的好故事。

**存储架构**：本地磁盘 → 对象存储（MinIO/S3 协议）的演进理由（无限扩容、生命周期管理、EC 纠删码）；缩略图生成（图片异步处理 + CDN 分发）、分享链接（签名 URL 防盗链 + 过期时间）、在线预览（PDF/Office 转换）。

**安全与权限**：目录权限（私有/共享/加密提取码）、越权访问防护（URL 不可猜测——UUID + 服务端校验归属）。面试高频：分片上传与断点续传实现、秒传原理、对象存储与文件系统区别、海量小文件的存储优化、分享链接的安全设计。

# 项目演进路线与推荐资源

**演进路线**：基础版（上传下载 + 目录管理）→ 进阶版（分片上传 + 断点续传 + 秒传）→ 完整版（MinIO 对象存储、缩略图异步生成、签名分享链接、引用计数删除策略）。附实测数据（1GB 文件分片上传耗时对比、秒传命中率）让简历可信。

**推荐资源**：MDN File API（Blob.slice 与 FormData）；MinIO 官方文档（S3 兼容接口与预签名 URL）；《Designing Data-Intensive Applications》（存储与编码章节）；阿里云 OSS 最佳实践文档（分片上传的工业级设计参考，公开可查）。
