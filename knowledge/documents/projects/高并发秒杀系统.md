# 高并发秒杀系统

## 项目概述

从零构建一个支撑高并发的商品秒杀系统，通过四个版本逐步优化迭代，从单机QPS几百提升到上万级别。秒杀系统是后端校招面试中最经典的分布式项目题材，涵盖缓存、消息队列、限流、分布式事务等几乎所有核心技术点。

项目采用渐进式开发思路：V1基础版跑通业务流程，V2引入缓存大幅提升性能，V3接入消息队列实现削峰填谷，V4打造生产级高可用架构。每个版本都有明确的性能指标和技术难点，帮助你循序渐进地掌握高并发系统设计的精髓。

## 核心功能

### V1 基础版（单机MySQL）
- 商品列表与秒杀详情页
- 基于数据库事务的下单逻辑
- 悲观锁/乐观锁防止商品超卖
- 用户登录与权限校验
- 订单创建与支付流程

### V2 缓存优化版（Redis）
- Redis预扣库存，减少数据库压力
- 商品信息缓存预热
- 本地缓存（Caffeine）+ Redis多级缓存
- 缓存穿透/击穿/雪崩解决方案
- 性能提升10倍以上

### V3 消息队列版（RocketMQ）
- RocketMQ异步下单，削峰填谷
- 事务消息保证缓存与数据库最终一致性
- 消费失败重试与死信队列
- 秒杀结果异步通知
- 流量洪峰平滑处理

### V4 生产级架构
- Sentinel限流熔断与降级策略
- 多级缓存架构与内存标记优化
- 数据一致性定时对账机制
- Prometheus + Grafana监控告警
- 分布式锁与接口幂等性设计
- Nginx层限流与负载均衡

## 技术栈详解

**Java 17 + Spring Boot 3**：项目基础框架，利用虚拟线程等新特性进一步提升并发能力。Spring Boot 3的原生镜像支持也为后续云原生部署打下基础。

**MySQL**：作为最终的数据存储载体，重点在于事务隔离级别、行锁/表锁机制、索引优化。秒杀场景下需要深入理解乐观锁（version字段）与悲观锁（select for update）的适用场景。

**Redis**：秒杀系统性能提升的核心组件。String类型扣减库存、Hash存储商品信息、Set维护已购用户名单、Lua脚本保证原子操作。同时要解决缓存穿透（布隆过滤器）、缓存击穿（互斥锁/永不过期）、缓存雪崩（过期时间打散）三大问题。

**RocketMQ**：用于异步下单和流量削峰。重点掌握同步/异步/单向发送方式、事务消息机制、消费重试与死信队列、消息幂等性处理。RocketMQ的事务消息是保证缓存与数据库最终一致性的关键。

**Spring Cloud Alibaba（Sentinel + Nacos）**：Sentinel实现限流熔断，支持QPS限流、线程数隔离、降级、热点参数限流等。Nacos作为服务注册与配置中心，支撑微服务架构下的服务治理。

**Nginx**：前端入口层，负责静态资源服务、反向代理、负载均衡。配合limit_req模块实现入口层限流，将恶意流量挡在系统之外。

**Docker + Kubernetes**：容器化部署与编排，实现弹性伸缩。秒杀活动开始前扩容Pod，结束后自动缩容，节约资源成本。

## 实现步骤

1. **需求分析与数据库设计**：梳理秒杀业务流程，设计商品表、订单表、秒杀商品表，建立合理索引。

2. **V1基础版开发**：搭建Spring Boot项目骨架，实现商品CRUD、用户登录、下单接口。先用悲观锁实现不超卖，再改为乐观锁对比性能差异。

3. **压力测试与瓶颈分析**：使用JMeter压测V1版本，记录QPS、响应时间、错误率等指标，定位数据库瓶颈。

4. **V2缓存优化**：引入Redis，实现商品信息缓存与库存预扣。开发缓存预热脚本，添加布隆过滤器防穿透。使用Caffeine作为本地缓存一级，Redis作为二级缓存。

5. **V3消息队列接入**：引入RocketMQ，将同步下单改为异步处理。实现事务消息：扣减缓存→发送半消息→执行本地事务→提交/回滚消息。

6. **V4生产级加固**：接入Sentinel配置限流规则，实现接口幂等性（Token机制）。添加定时任务对账，修复缓存与数据库不一致。集成监控告警。

7. **部署与全链路压测**：Docker容器化部署，搭建K8s集群或使用云服务，进行全链路压测验证系统承载能力。

## 面试亮点

- **怎么防止超卖？**：数据库层面用乐观锁（version版本号）或悲观锁（select for update）；缓存层面用Redis + Lua脚本原子扣减；内存标记快速过滤无效请求。
- **怎么处理高并发？**：分层限流（Nginx层 + 应用层 + 服务层）；多级缓存（本地缓存 + Redis）；消息队列削峰填谷；服务降级与熔断；水平扩展。
- **缓存和数据库一致性怎么保证？**：先更新数据库再删缓存（Cache Aside Pattern）；异步订阅binlog更新缓存；定时对账任务兜底；事务消息保证最终一致。
- **消息队列怎么保证不丢消息？**：生产者同步发送 + 重试机制；Broker同步刷盘 + 主从同步；消费者手动确认 + 消费重试 + 死信队列。
- **怎么限流？有哪些限流算法？**：计数器、滑动窗口、漏桶、令牌桶四种算法。Sentinel默认使用滑动窗口，支持QPS限流和线程数隔离。
- **秒杀系统的优化思路？**：将请求尽量在上游拦截掉，越下游越少请求。从页面静态化→CDN→Nginx限流→缓存拦截→MQ异步→数据库，层层过滤。
