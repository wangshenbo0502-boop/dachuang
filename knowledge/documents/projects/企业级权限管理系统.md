# 企业级权限管理系统

## 项目概述

搭建一个企业级的用户角色权限管理系统（RBAC），这是后端开发面试中最常被问到的项目类型。

## 核心功能

- 用户管理（CRUD + 分页 + 搜索）
- 角色管理（角色-权限关联）
- RBAC 动态权限控制
- 操作日志（AOP + 数据库）
- 接口限流
- Swagger 接口文档
- Docker Compose 一键部署

## 技术收获

- 深入理解 RBAC 权限模型
- Spring Security 自定义认证流程
- Redis 缓存用户权限信息
- AOP 实现操作日志
- Docker 容器化部署

## 适合人群

有 Spring Boot 基础、准备找后端工作的同学

# 技术难点与面试展开点

权限系统的核心是**认证（Authentication，你是谁）与授权（Authorization，你能干什么）**的分离，这个项目把企业软件最通用的 RBAC 做透。**RBAC 模型演进**要能逐层讲：RBAC0（用户-角色-权限三层）、RBAC1（角色继承）、RBAC2（约束：互斥角色/基数限制）、数据权限（部门/本人/本部门及以下——与功能权限正交的行级过滤，是真实企业需求）。

**技术实现要点**：表设计（用户表、角色表、权限表、两张关联表，数据权限加部门表）、JWT 无状态认证的完整方案（access token 短效 + refresh token 续期 + 退出黑名单）、接口级鉴权（注解 + AOP 或网关层统一拦截）、前端路由权限（动态路由表按角色过滤）与按钮级权限（自定义指令 v-permission）。

**安全细节**是面试加分面：密码存储（bcrypt 加盐哈希，绝不明文/MD5）、登录防爆破（失败锁定与验证码）、越权测试（水平越权——改 ID 访问他人资源；垂直越权——普通用户调管理员接口，服务端必须再校验）。

**面试高频**：RBAC 表结构手画、JWT 组成与放哪（localStorage vs HttpOnly Cookie 的 XSS/CSRF 权衡）、token 过期与并发登录策略、数据权限如何实现（SQL 拦截器拼接 where 条件）、Spring Security/Shiro 的过滤器链。

# 项目演进路线与推荐资源

**演进路线**：基础版（RBAC0 五表 + JWT 登录）→ 进阶版（按钮级权限、数据权限 SQL 拦截、操作审计日志）→ 完整版（越权测试用例集 + 登录防爆破 + 单元测试覆盖核心鉴权逻辑）。"安全测试用例表"（水平/垂直越权各 N 例全部拦截）是这份简历最有专业感的亮点。

**推荐资源**：Spring Security 官方文档（过滤器链与授权模型）；OWASP（认证与访问控制 Cheat Sheet）；JWT RFC 7519 规范（token 结构与声明）；若依（RuoYi）开源后台（企业级 RBAC 的参考实现，注意加入自己的改造点避免纯套壳）。
