# 全栈项目实战：从0到1上线

## 指南概述

完整讲解一个全栈项目从需求分析到上线部署的全流程，包含前后端开发、数据库设计、部署运维。适合想完整走一遍项目流程、积累全栈经验的同学。

## 技术栈与工时

**技术栈**：Vue3/React + TypeScript + Node.js/Java + MySQL + Redis + Docker + Nginx

**预计工时**：约 80 小时
- 需求分析与设计：10 小时
- 后端开发：30 小时
- 前端开发：25 小时
- 部署上线：10 小时
- 测试与优化：5 小时

## 项目选题建议

| 项目类型 | 难度 | 特点 | 适合方向 |
|---------|------|------|---------|
| 博客系统 | 入门 | 功能明确，技术点全面 | 全栈入门 |
| 待办/任务管理 | 入门 | 简单实用，快速出 MVP | 前后端基础 |
| 论坛/社区 | 进阶 | 互动性强，用户体系完整 | 后端/全栈 |
| 在线工具站 | 中等 | 实用性强，容易传播 | 前端为主 |
| 个人作品集 | 入门 | 展示用，注重设计感 | 前端方向 |

## 阶段 1：需求分析与设计

### 功能需求梳理
先写需求文档，明确做什么、不做什么。推荐用户故事方式：
- 作为游客，我可以浏览文章列表
- 作为注册用户，我可以发布文章
- 作为管理员，我可以管理用户

画功能结构图，排好优先级：MVP 版本做哪些，后续迭代做哪些。

### 技术选型
根据项目特点和个人技术栈选择：
- 前端：Vue3（上手快）或 React（生态好）
- 后端：Node.js（语言统一）或 Java（就业面广）
- 数据库：MySQL（关系型）或 MongoDB（文档型）
- 缓存：Redis（必选）
- 部署：Docker + 云服务器

原则：用你最熟悉的技术，不要为了炫技而堆砌技术栈。

### 数据库设计
先画 ER 图，理清实体关系：
- 一对一：用户 - 用户详情
- 一对多：用户 - 文章、文章 - 评论
- 多对多：文章 - 标签、用户 - 角色

表设计要点：
- 主键用 bigint 或 varchar(32)
- 必须有 create_time、update_time 字段
- 逻辑删除用 is_deleted，不要物理删除
- 常用查询字段加索引

### 接口设计
遵循 RESTful API 规范：
- GET /articles - 获取列表
- POST /articles - 创建
- PUT /articles/:id - 更新
- DELETE /articles/:id - 删除

统一返回格式：
```json
{ "code": 200, "message": "success", "data": {} }
```
用 Swagger 写接口文档，前后端并行开发的基础。

## 阶段 2：后端开发

### 项目初始化与用户模块
- 分层结构：controller、service、mapper、entity、config、utils
- 配置数据库（ORM 框架）、Redis、日志、多环境区分
- 用户注册/登录：BCrypt 加密 + JWT 令牌验证
- RBAC 角色权限模型 + 中间件登录/权限校验

### 核心业务与工程化
- CRUD 接口、分页查询、文件上传、搜索筛选、操作日志
- 统一返回格式 + 全局异常处理
- 参数校验（必填/格式/长度/自定义）
- Swagger 接口文档 + 核心业务单元测试

## 阶段 3：前端开发

### 项目初始化与路由状态
用 Vite 创建项目（Vue/React + TypeScript），配置 ESLint + Prettier、路径别名、环境变量。

基础依赖：Element Plus/Ant Design、Vue Router/React Router、Pinia/Zustand、Axios、Tailwind CSS/SCSS。

路由结构分公开/登录/管理员三级，配合路由守卫做权限校验。全局状态存用户信息、主题，Token 等存 localStorage。

### 组件开发与接口联调
- 组件层级：布局组件 → 业务组件 → 页面级组件
- 开发顺序：先做布局，再做公共组件，最后写页面
- Axios 封装：统一 baseURL、拦截器、错误处理
- API 按业务模块组织，不要散落

### 样式与适配
- 响应式布局 + 媒体查询，适配移动端
- 暗色模式用 CSS 变量实现，骨架屏做加载占位

## 阶段 4：部署上线

### 云服务器配置
- 新手推荐阿里云/腾讯云学生机，1 核 2G 起步
- 操作系统选 Ubuntu 22.04
- 安全组开放 22、80、443 端口
- SSH 密钥登录，禁用密码登录
- 安装 Git、Node.js、Docker、Nginx

### Docker 容器化
前后端和数据库都用 Docker 部署：
- Dockerfile：前端用 nginx 镜像，后端用 node/jdk 镜像
- docker-compose.yml：编排多个服务
- 数据卷挂载：数据库数据、上传文件持久化
- 内部网络：服务之间用内部网络通信

### Nginx 反向代理
Nginx 作为入口，负责：
- 静态文件服务：前端打包产物
- 反向代理：/api 转发到后端服务
- Gzip 压缩：减少传输体积
- 缓存策略：静态资源加缓存头

### 域名与 HTTPS
- 购买域名：.com 或 .cn 后缀
- 域名备案：国内服务器必须备案，约 1-2 周
- DNS 解析：域名指向服务器 IP
- HTTPS 证书：Let's Encrypt 免费证书
- Nginx 配置 HTTPS，强制 HTTP 跳转

### CI/CD 自动化部署
提交代码后自动部署：
- GitHub Actions / GitLab CI
- 流程：提交 → 测试 → 构建 → 部署
- 密钥和环境变量不硬编码
- 版本回滚：出问题一键回退

## 阶段 5：运营与迭代

- **数据统计**：接入百度统计/GA，关注 PV、UV、留存率
- **用户反馈**：加反馈入口，建用户群，收集第一手意见
- **功能迭代**：小步快跑，每周或每两周一个小版本
- **持续优化**：重构穿插在迭代中，不要等技术债堆太多
