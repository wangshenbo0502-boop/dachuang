# SaaS短链接系统

## 项目概述

构建一个高可用、高性能的SaaS短链接服务，支持海量短链接生成与访问统计。短链接系统是2026年后端校招的热门项目题材，涵盖分布式ID、分库分表、缓存架构、异步统计、多租户隔离等核心技术点，业务场景清晰且技术覆盖面广。

项目采用SaaS多租户架构，支持用户分组管理短链接，具备完整的后台管理功能。从短链接生成算法选型到高性能302跳转，从海量数据统计到分库分表设计，全方位锻炼后端系统设计能力。

## 核心功能

### 短链接生成与跳转
- 短链接生成（自增ID/哈希算法/雪花算法对比实现）
- 短链接302重定向，高性能毫秒级跳转
- 自定义短链接后缀，支持品牌化
- 短链接有效期设置，过期自动失效
- 访问密码保护，私密链接安全可控

### 访问统计与分析
- PV/UV实时统计
- 访问地区分布（IP解析 + 地理位置）
- 设备/浏览器/操作系统分布
- 访问趋势折线图与热力图
- Top访问来源与Referer分析

### 后台管理与SaaS能力
- 短链接分组管理，多租户数据隔离
- 批量生成与导入导出（Excel/CSV）
- 数据看板与可视化报表
- 用户注册登录与权限管理
- 短链接编辑、删除、启用/禁用

### 运维与监控
- 操作日志审计
- 接口限流与防刷
- 异常告警与监控大盘
- 系统性能指标监控

## 技术栈详解

**Java 17 + Spring Boot 3**：后端核心框架。利用Spring Boot 3的新特性提升开发效率，Java 17的record模式、sealed类等新语法让代码更简洁。

**Spring Cloud Alibaba（Nacos + Sentinel）**：Nacos作为服务注册发现与配置中心，Sentinel实现接口限流与熔断降级，保护短链接生成接口免受恶意刷量攻击。

**MySQL + ShardingSphere**：MySQL作为主存储，短链接数据量巨大（亿级），使用ShardingSphere-JDBC进行分库分表。按短链接后缀哈希分库分表，水平扩展存储能力。设计时需考虑分片键选择、跨分片查询等问题。

**Redis**：核心性能组件。短链接映射缓存（String/Hash）、访问计数（INCR原子操作）、布隆过滤器（防穿透）、限流计数器等。本地缓存Caffeine + Redis构成二级缓存，进一步降低Redis压力。

**RocketMQ**：异步解耦核心组件。访问日志异步写入（削峰填谷）、统计数据异步聚合、通知消息异步发送。通过消息队列将实时跳转与离线统计解耦，保证跳转接口极致性能。

**Elasticsearch**：用于短链接访问日志的检索与分析。支持按时间、地区、短链接ID等多维度查询，为数据看板提供检索能力。同时配合Kibana做日志可视化。

**Vue3 + Element Plus**：后台管理系统前端。提供分组管理、短链接CRUD、数据看板等可视化操作界面。

## 实现步骤

1. **需求分析与架构设计**：梳理短链接业务流程，设计整体架构图，确定技术选型。重点对比短链接生成算法：自增ID、哈希算法（MD5/SHA）、雪花算法、Base62编码等方案的优劣。

2. **数据库设计与分库分表**：设计短链接表、分组表、用户表、访问日志表。集成ShardingSphere，配置分片规则，验证分库分表效果。

3. **核心功能开发**：实现短链接生成接口（支持自定义后缀、有效期、密码）、302跳转接口。编写单元测试保证功能正确性。

4. **缓存架构搭建**：引入Redis，实现短链接映射缓存。添加布隆过滤器防止缓存穿透。接入Caffeine本地缓存，构建二级缓存架构。

5. **异步统计接入**：引入RocketMQ，跳转时异步发送访问日志消息。消费端写入ES与MySQL统计数据表。实现PV/UV、地区分布等统计算法。

6. **SaaS后台管理**：开发用户注册登录、分组管理、短链接管理后台。实现数据可视化看板，接入ECharts展示统计图表。

7. **性能优化与压测**：使用JMeter进行压力测试，定位性能瓶颈。优化数据库索引、缓存策略、JVM参数。目标：单节点跳转QPS达到1万+。

8. **部署上线**：Docker容器化，Docker Compose编排所有服务。配置Nginx反向代理与HTTPS。部署到云服务器并进行线上验证。

## 面试亮点

- **短链接生成算法有哪些？各有什么优缺点？**：自增ID（简单有序但易被遍历推测数量）、哈希算法（MD5/SHA取前几位，冲突概率高）、雪花算法（分布式唯一，长度稍长）、自增ID + Base62编码（推荐方案，短且有序）。需对比长度、唯一性、安全性、实现复杂度。

- **怎么处理高并发访问？**：多级缓存（本地缓存 + Redis缓存热点短链）、布隆过滤器防穿透、Nginx层静态资源缓存、接口限流、读写分离、水平扩展。跳转接口极致优化，只做缓存查询+302重定向。

- **分库分表怎么设计？**：分片键选择（短链接后缀哈希）、分片数量规划（预估数据量+增长）、跨分片查询方案（ES辅助检索）、扩容策略（双倍扩容+数据迁移）、ShardingSphere实际配置与踩坑。

- **海量数据怎么统计？**：读写分离，统计查询走从库/ES；预聚合统计，按小时/天维度提前计算；异步写入，MQ消峰后批量入库；Bitmap/HyperLogLog等概率数据结构节省空间；冷热数据分层，历史数据归档。

- **缓存穿透/击穿/雪崩怎么解决？**：穿透→布隆过滤器 + 空值缓存；击穿→互斥锁 + 热点数据永不过期；雪崩→过期时间随机打散 + 多级缓存 + 服务降级。

- **怎么保证短链接不重复？**：数据库唯一索引兜底、生成后校验唯一性并冲突重试、使用号段模式批量预分配ID减少DB压力。
