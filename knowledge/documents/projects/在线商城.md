# 在线商城（电商前端）

## 项目概述

独立完成一个电商网站的前端全部页面和交互逻辑。重点锻炼复杂状态管理和组件设计能力。

## 核心功能

- 商品列表（搜索/筛选/排序/分页）
- 商品详情页
- 购物车（增删改查 + 本地持久化）
- 订单确认页
- 个人中心（订单列表/收藏）
- 骨架屏 + 懒加载

## 技术收获

- 复杂页面的组件拆分（至少15个组件）
- Pinia/Zustand 管理全局购物车状态
- Axios 拦截器 + 请求缓存
- 性能优化（虚拟列表、图片懒加载、防抖节流）

## 适合人群

有 2-3 个月前端学习经验的学生

## 前置技能

- Vue.js/React 熟练
- TypeScript 基础
- Pinia/Zustand 基础

# 技术难点与面试展开点

电商是业务复杂度最高的练兵场景，商城项目的深度取决于是否覆盖**交易核心链路的并发问题**。三个必做难点：

**库存扣减**：下单减库存的三种方案对比（下单减/支付减/预占）、超卖问题的三层防御（数据库乐观锁版本号 → Redis 预扣 + Lua 原子化 → 消息队列异步落库），能讲清"Redis 扣成功了但订单创建失败怎么补偿"（事务消息/对账）就超过了大多数候选人。

**订单与支付**：订单状态机（待支付/已支付/已发货/已完成/已取消）、订单超时自动取消的三种实现（定时轮询/延迟队列/Redis 过期监听的可靠性对比）、支付回调的幂等处理（唯一流水号 + 状态机校验）、对账机制。

**秒杀模块**（可选进阶）：库存预热到 Redis、限流（前端答题/网关限流）、削峰（MQ 异步下单）、防黄牛（接口限频、令牌校验）。

**商品与搜索**：商品详情多表聚合的缓存策略（多级缓存 + 缓存一致性）、搜索功能（MySQL LIKE → ES 的演进理由：分词与相关性排序）。面试高频：超卖怎么防、订单超时关闭的方案对比、支付回调幂等、缓存与数据库一致性、为什么电商都在用消息队列。

# 项目演进路线与推荐资源

**演进路线**：基础版（商品/购物车/订单 CRUD）→ 进阶版（库存防超卖三层方案、订单超时关闭、支付回调幂等）→ 完整版（秒杀模块 + 压测报告：单机 QPS、超卖 0 事件的验证数据、缓存一致性方案对比）。压测过程与调优前后对比是这个项目区别于"烂大街商城"的分水岭。

**推荐资源**：美团技术博客（秒杀与订单系统实践文章）；《Java 并发编程实战》（原子性与锁）；RocketMQ 官方文档（事务消息与延迟消息）；Seata 官方文档（分布式事务场景对照）。

# 简历定位

适合后端方向（Java/Go）。定位示例："电商交易链路：Redis 预扣库存防超卖（压测 0 超卖）、延迟队列自动关单、支付回调幂等，接口 P99 < 80ms"。用并发正确性指标替代功能罗列，立刻与普通商城项目拉开差距。
