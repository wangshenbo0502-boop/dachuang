# 云原生微服务部署平台

## 项目概述

基于Kubernetes构建一个完整的云原生应用部署与运维平台，实践DevOps全流程。这是云原生/DevOps岗位的必备项目，涵盖容器化、CI/CD、监控告警、日志收集、服务网格、基础设施即代码等云原生核心技术栈。

项目从Docker容器化入手，逐步深入Kubernetes集群管理、CI/CD流水线搭建、可观测性体系建设、服务网格流量治理、基础设施自动化等模块。通过亲手搭建一套完整的云原生平台，深入理解CNCF生态的各个组件及其协同工作原理。

## 技术栈详解

**Kubernetes**：云原生技术栈的核心，容器编排的事实标准。需要深入理解其架构（Master/Node）、核心组件（kube-apiserver、etcd、kube-scheduler、kube-controller-manager、kubelet、kube-proxy）、以及各种资源对象的使用场景。

**Docker & Containerd**：容器运行时基础。掌握Dockerfile编写、镜像构建优化、容器网络与存储原理。理解容器本质是Linux Namespace + Cgroups的隔离技术。

**Helm**：Kubernetes的包管理工具。通过Chart模板化管理K8s应用，支持版本管理、依赖管理、参数化配置。是企业级应用发布的标准方式。

**Jenkins / GitLab CI**：CI/CD引擎。Jenkins功能强大插件丰富，GitLab CI与代码仓库深度集成。掌握Pipeline as Code写法，实现从代码到上线的全自动化。

**Prometheus + Grafana**：监控体系核心。Prometheus基于拉模型采集指标，使用PromQL查询；Grafana提供丰富的可视化图表。配合AlertManager实现告警分级与多路通知。

**ELK Stack（Elasticsearch + Logstash + Kibana）/ Loki**：日志收集方案。ELK功能全面但资源消耗大，Loki轻量高效更适合K8s场景。配合Filebeat/Promtail采集容器日志。

**Istio**：服务网格代表产品。基于Envoy Sidecar实现流量治理、安全、可观测性，业务代码无侵入。掌握流量拆分、故障注入、熔断重试等核心功能。

**Terraform**：基础设施即代码工具。使用HCL语言声明式定义云资源，支持多云环境。实现基础设施的版本管理与自动化部署。

**Go / Python**：云原生领域的主力编程语言。Go是K8s、Docker、Prometheus等项目的实现语言；Python广泛用于运维脚本与自动化工具开发。

## 实现步骤

1. **环境准备与Docker基础**：安装Docker，练习Dockerfile编写与镜像构建。理解镜像分层、多阶段构建、镜像瘦身等最佳实践。使用Docker Compose编排一个多服务应用。

2. **K8s集群搭建**：使用kubeadm搭建3节点K8s集群（或使用minikube/kind快速起步）。熟悉kubectl命令，掌握Pod、Deployment、Service等核心资源的YAML编写。

3. **应用部署实践**：将一个微服务应用（如Spring Cloud应用）容器化并部署到K8s。配置ConfigMap、Secret、Ingress、PV/PVC等资源，实现完整的应用生命周期管理。

4. **CI/CD流水线搭建**：部署Jenkins/GitLab Runner，编写Pipeline脚本。实现：代码提交→触发构建→单元测试→代码质量扫描→镜像构建→镜像推送→部署到K8s。配置多环境部署流程。

5. **监控告警体系建设**：部署Prometheus + Grafana + AlertManager。配置Node Exporter、cAdvisor、kube-state-metrics采集集群指标。搭建集群监控大盘、应用监控大盘。配置钉钉/邮件告警通知。

6. **日志系统搭建**：部署EFK（Elasticsearch + Filebeat + Kibana）或Loki + Promtail方案。配置日志采集、解析、检索。实现日志与链路追踪关联。

7. **服务网格接入**：安装Istio，为应用注入Sidecar。配置流量路由（灰度发布）、熔断、重试、超时等策略。部署Kiali查看服务拓扑。

8. **基础设施即代码**：使用Terraform管理云资源（如阿里云ECS、VPC等）。编写Ansible Playbook实现服务器批量初始化。

9. **高级特性实践**：配置HPA自动扩缩容、NetworkPolicy网络策略、RBAC权限管理。实践蓝绿部署、金丝雀发布等高级发布策略。

10. **综合验收与优化**：模拟真实业务场景进行全链路压测，验证平台稳定性。进行成本优化与安全加固。

## 面试亮点

- **K8s核心组件有哪些？各自作用？**：Master节点：kube-apiserver（统一入口，REST API）、etcd（分布式存储，保存集群状态）、kube-scheduler（调度Pod到Node）、kube-controller-manager（控制器管理器）。Node节点：kubelet（管理Pod生命周期）、kube-proxy（Service网络代理）、容器运行时（Docker/containerd）。

- **Pod的生命周期？**：Pending（等待调度）→ Running（运行中）→ Succeeded（成功退出）/ Failed（失败退出）/ Unknown（失联）。Pod重启策略：Always、OnFailure、Never。Init Container先于主容器启动。

- **Service有哪几种类型？**：ClusterIP（集群内部访问，默认）、NodePort（通过节点端口暴露）、LoadBalancer（云厂商负载均衡器，NodePort的超集）、ExternalName（通过CNAME映射到外部服务）。Service通过Label Selector匹配Pod，kube-proxy维护iptables/ipvs规则。

- **怎么实现蓝绿部署/金丝雀发布？**：蓝绿部署→两套环境，流量一次性切换，回滚快但资源翻倍。金丝雀发布→逐步放量，风险可控。K8s原生可通过调整Deployment副本数实现；生产环境常用Ingress Controller（Nginx/Traefik）权重配置、Istio流量拆分、或Argo Rollouts Operator。

- **监控告警怎么设计？**：三层监控体系——基础设施层（节点CPU/内存/磁盘）、平台层（K8s集群状态、Pod健康）、应用层（业务指标、接口QPS/延迟）。Prometheus采集 + Grafana展示 + AlertManager告警。告警分级：P0（电话）、P1（钉钉+短信）、P2（邮件）。避免告警风暴，设置合理的阈值与抑制规则。

- **K8s中Pod是怎么调度的？**：调度流程：kube-scheduler watch到新Pod→过滤不符合条件的节点（预选Predicate）→对剩余节点打分（优选Priority）→选择最高分节点→通过apiserver绑定。影响调度的因素：资源请求（CPU/内存）、节点选择器（nodeSelector）、亲和性（Affinity）、污点与容忍（Taint/Toleration）、拓扑分布约束。

- **ConfigMap和Secret的区别？**：都用于存储配置信息，ConfigMap存非敏感数据，Secret存敏感信息（密码、证书、Token）。Secret数据用Base64编码（非加密，生产环境建议用Sealed Secrets或Vault）。两者都支持挂载为文件或环境变量。
