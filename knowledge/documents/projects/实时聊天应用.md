# 技术难点与面试展开点

即时通讯（IM）系统的核心是**长连接与消息可靠性**，这两个方向的技术深度远超普通 CRUD 项目。

**长连接通道**：WebSocket 握手过程（HTTP Upgrade）与心跳保活（断网感知）、连接的网关化管理（用户 ID → 网关节点的映射存 Redis，实现跨节点推送）、多端登录的消息同步（seq 序号 + 各端 ack）。对比轮询/长轮询/SSE/WebSocket 四种方案的适用场景是基础必考。

**消息可靠性投递**是 IM 的灵魂：不丢、不重、不乱序——客户端发送带客户端消息 ID（幂等去重）、服务端落库后再推送、接收方 ack 确认、超时未 ack 重推、端上按 seq 排序与去重；离线消息的存储与拉取（收件箱模型 vs 写扩散）。**消息已读回执**与**撤回**（时限校验 + 双端状态同步）是贴近真实产品的细节。

**进阶亮点**：群聊的写扩散/读扩散选型、消息漫游（历史消息分页拉取）、端到端加密的概念级讨论、敏感词过滤（DFA/AC 自动机——高频算法题）。面试高频：WebSocket 与 HTTP 长轮询区别、如何保证消息不丢不重、心跳的作用与间隔设计、群消息扩散方案、AC 自动机原理。

# 项目演进路线与推荐资源

**演进路线**：基础版（单机 WebSocket + 消息落库）→ 进阶版（心跳保活、离线消息、已读回执、多端同步 seq）→ 完整版（集群部署：网关层 + 逻辑层分离、跨节点路由、压测：单机长连接数与消息投递延迟 P99）。

**推荐资源**：MDN WebSocket 文档（协议细节）；Netty 官方文档（Java 长连接框架）或 Go 的 gorilla/websocket；《大型网站技术架构》（消息系统章节）；OpenIM 与 WildfireChat 等开源 IM（架构对标）。

# 简历定位

适合后端方向。定位示例："IM 系统：WebSocket 心跳保活、seq 序号保证多端消息不丢不重不乱序、离线消息收件箱，单机 1 万长连接，消息投递 P99 < 50ms"。消息可靠性设计是本项目的核心叙事，面试官追问概率极高，务必吃透。
