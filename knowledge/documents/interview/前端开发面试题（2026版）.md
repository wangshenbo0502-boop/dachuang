### Q1: 说说 JavaScript 的事件循环机制？宏任务和微任务？

- **类别**: JavaScript基础
- **难度**: 中等
- **频率**: 极高

<details>
<summary>答题要点</summary>

**事件循环（Event Loop）**：JavaScript 单线程异步执行的核心机制，负责协调调用栈、任务队列和渲染进程。

**执行流程**：
1. 同步代码在调用栈中依次执行
2. 遇到异步 API（setTimeout、Promise 等），将回调交给对应 Web API 处理
3. Web API 完成后，将回调推入任务队列
4. 调用栈清空后，事件循环开始工作
5. 先执行所有微任务，再执行一个宏任务，如此循环

**宏任务（Macrotask）**：
- 包括：script 整体代码、setTimeout、setInterval、setImmediate（Node）、I/O、UI 渲染
- 每个宏任务执行完后，会检查并清空微任务队列

**微任务（Microtask）**：
- 包括：Promise.then/catch/finally、MutationObserver、process.nextTick（Node）
- 在当前宏任务结束后、下一个宏任务开始前全部执行
- 微任务中产生的新微任务也会在当前轮次执行完毕

**执行顺序口诀**：同步 → 微任务 → 宏任务 → 微任务 → 宏任务 → ...

</details>

### Q2: 闭包是什么？应用场景？内存泄漏？

- **类别**: JavaScript基础
- **难度**: 中等
- **频率**: 极高

<details>
<summary>答题要点</summary>

**闭包（Closure）**：函数与其词法环境的组合。内部函数可以访问外部函数作用域中的变量，即使外部函数已经执行完毕。

**形成条件**：
1. 函数嵌套函数
2. 内部函数引用外部函数的变量
3. 内部函数被返回或保存到外部

**应用场景**：
- **数据私有化**：模拟私有变量，避免全局污染
- **函数柯里化**：固定部分参数，返回新函数
- **防抖/节流**：闭包保存定时器 ID 和上一次执行时间
- **模块化**：IIFE 立即执行函数创建独立作用域
- **事件回调**：回调函数访问外部作用域变量

**内存泄漏问题**：
- 闭包会持有外部函数的作用域，导致变量无法被 GC 回收
- 常见场景：事件监听器未移除、定时器未清除、DOM 引用未释放
- 避免方法：手动解除引用（变量置 null）、移除事件监听、清除定时器

</details>

### Q3: 原型和原型链？new 操作符做了什么？

- **类别**: JavaScript基础
- **难度**: 中等
- **频率**: 极高

<details>
<summary>答题要点</summary>

**原型（Prototype）**：每个函数都有一个 prototype 属性，指向一个对象，这个对象是该函数所有实例的原型。

**`__proto__`**：每个对象都有 `__proto__` 属性，指向其构造函数的 prototype 对象。

**原型链**：当访问对象的属性时，先在对象本身找，找不到就沿着 `__proto__` 向上找，直到 null（Object.prototype.__proto__），这条链就是原型链。

**核心关系**：
```
实例.__proto__ === 构造函数.prototype
构造函数.prototype.constructor === 构造函数
函数.__proto__ === Function.prototype
Object.prototype.__proto__ === null
```

**new 操作符做了什么**：
1. 创建一个新的空对象
2. 将新对象的 `__proto__` 指向构造函数的 prototype
3. 将构造函数的 this 绑定到新对象，执行构造函数
4. 如果构造函数返回对象，则返回该对象；否则返回新对象

</details>

### Q4: 深浅拷贝的区别？如何实现深拷贝？

- **类别**: JavaScript基础
- **难度**: 中等
- **频率**: 极高

<details>
<summary>答题要点</summary>

**区别**：
| 类型 | 拷贝层级 | 修改拷贝是否影响原对象 |
|------|----------|----------------------|
| 浅拷贝 | 只拷贝第一层引用 | 基本类型不影响，引用类型影响 |
| 深拷贝 | 递归拷贝所有层级 | 完全独立，互不影响 |

**浅拷贝实现**：
- `Object.assign({}, obj)`
- 展开运算符 `{...obj}`
- 数组：`slice()`、`concat()`、`[...arr]`

**深拷贝实现**：

1. **JSON.parse(JSON.stringify(obj))**
   - 简单但有缺陷：不能拷贝函数、undefined、Symbol、循环引用、Date、RegExp

2. **递归实现**：
```
function deepClone(obj, map = new WeakMap()) {
    if (obj === null || typeof obj !== 'object') return obj
    if (map.has(obj)) return map.get(obj)  // 处理循环引用
    const clone = Array.isArray(obj) ? [] : {}
    map.set(obj, clone)
    for (let key in obj) {
        if (obj.hasOwnProperty(key)) {
            clone[key] = deepClone(obj[key], map)
        }
    }
    return clone
}
```

3. **第三方库**：lodash 的 `_.cloneDeep()`，生产环境推荐使用

</details>

### Q5: Vue 的响应式原理？Vue2 的 Object.defineProperty 和 Vue3 的 Proxy 区别？

- **类别**: Vue原理
- **难度**: 中等
- **频率**: 极高

<details>
<summary>答题要点</summary>

**Vue2 响应式原理**：
- 数据劫持 + 发布订阅模式
- 使用 `Object.defineProperty` 劫持 data 中每个属性的 getter/setter
- 每个属性对应一个 Dep 收集器，收集依赖它的 Watcher
- 属性变化时，dep.notify() 通知所有 Watcher 更新视图

**Vue2 的缺点**：
- 无法监听对象属性的新增和删除（需用 Vue.set / Vue.delete）
- 无法监听数组下标变化和长度变化（通过重写数组 7 个方法实现）
- 深层嵌套对象需要递归遍历，性能开销大
- 初始化时就要遍历所有属性，启动慢

**Vue3 响应式原理**：
- 使用 ES6 的 Proxy 代理整个对象
- Reflect 操作原对象
- 懒代理：只有访问到属性时才递归代理下一层

**Proxy vs Object.defineProperty 对比**：
| 对比项 | Object.defineProperty | Proxy |
|--------|----------------------|-------|
| 代理粒度 | 属性级别 | 对象级别 |
| 新增属性 | 无法监听 | 可以监听 |
| 删除属性 | 无法监听 | 可以监听 |
| 数组 | 需特殊处理 | 原生支持 |
| 性能 | 初始化遍历全部属性 | 懒代理，按需响应 |
| 兼容性 | IE9+ | 不支持 IE |

</details>

### Q6: React Hooks 原理？useState/useEffect 实现机制？

- **类别**: React原理
- **难度**: 较难
- **频率**: 极高

<details>
<summary>答题要点</summary>

**Hooks 本质**：让函数组件拥有状态和生命周期能力的 API，底层依赖链表和 Fiber 架构。

**useState 原理**：
- 每个函数组件对应一个 Fiber 节点
- Fiber 节点上有一个 `memoizedState` 链表，存储所有 hooks 的状态
- 每个 hook 对应链表中的一个节点（按调用顺序排列）
- 首次渲染：按调用顺序依次创建 hook 节点，初始化 state
- 更新渲染：按调用顺序依次读取 hook 节点，返回当前 state 和 setter
- **为什么不能在条件/循环中使用 hooks**：会破坏链表顺序，导致状态错位

**useEffect 原理**：
- 同样存储在 `memoizedState` 链表中
- 每个 effect 包含：回调函数、依赖数组、清除函数
- 渲染阶段：收集所有 effect，存入 Fiber 的 updateQueue
- 提交阶段：
  1. 先执行上一轮的清除函数（如果依赖变化）
  2. 再执行本轮的 effect 回调
  3. 保存新的清除函数
- 依赖数组：每次渲染对比依赖项，变化才重新执行

**Hooks 调用规则**：
- 只在函数组件顶层调用
- 只在 React 函数中调用
- 依赖数组要完整，不能遗漏

</details>

### Q7: Virtual DOM 和 Diff 算法原理？React 和 Vue 的 Diff 区别？

- **类别**: 框架原理
- **难度**: 较难
- **频率**: 高

<details>
<summary>答题要点</summary>

**Virtual DOM**：
- 用 JS 对象描述真实 DOM 的结构和属性
- 状态变化时，生成新的虚拟 DOM 树，与旧树对比差异
- 将差异批量更新到真实 DOM，减少直接操作 DOM 的次数
- 优势：跨平台、批量更新、声明式编程

**Diff 算法核心策略**：
- 同层比较，不跨层（时间复杂度从 O(n³) 降到 O(n)）
- 不同类型的节点直接替换
- 同类型节点通过 key 标识复用

**React Diff**：
- 单指针从左到右遍历
- 三步优化策略：
  1. 旧节点和新节点都从左开始比较，相同则继续
  2. 旧节点尾和新节点尾比较，相同则继续
  3. 头尾交叉比较
- 最后剩下的用 map 找索引，进行移动/新增/删除

**Vue Diff**：
- 双指针（头头、尾尾、头尾、尾头）四种比较方式
- 同样用 key 建立旧节点索引 map
- 处理完首尾相同节点后，中间部分用最长递增子序列（LIS）优化移动次数
- 相比 React 的 Diff，Vue 的 LIS 优化减少了 DOM 移动操作

**主要区别**：
- React 从左向右遍历，用 key map 找位置
- Vue 用双端指针 + 最长递增子序列，移动次数更少
- 核心思想一致：同层比较、key 复用、最小化 DOM 操作

</details>

### Q8: TypeScript 的高级类型有哪些？泛型、条件类型、映射类型？

- **类别**: TypeScript
- **难度**: 较难
- **频率**: 高

<details>
<summary>答题要点</summary>

**泛型（Generics）**：
- 在定义函数/接口/类时不指定具体类型，使用时再指定
- `function identity<T>(arg: T): T { return arg }`
- 泛型约束：`<T extends Lengthwise>` 限制 T 必须有 length 属性
- 泛型工具类型：Partial、Required、Readonly、Pick、Omit、Record、Exclude、Extract

**条件类型（Conditional Types）**：
- `T extends U ? X : Y`，类似三元表达式
- 常用于类型推断和类型分发
- 例：`type NonNullable<T> = T extends null | undefined ? never : T`
- 分布式条件类型：当 T 是联合类型时，会分发到每个成员

**映射类型（Mapped Types）**：
- 遍历已有类型的属性，创建新类型
- `type Readonly<T> = { readonly [P in keyof T]: T[P] }`
- 常用：`Partial<T>`、`Required<T>`、`Readonly<T>`、`Record<K, V>`

**其他高级类型**：
- **infer 关键字**：在条件类型中推断类型，如 `ReturnType<T>`
- **模板字面量类型**：`` type Greeting = `Hello, ${T}` ``
- **索引类型**：`keyof T` 获取键，`T[K]` 获取值类型
- **交叉类型**：`A & B`，合并所有属性
- **联合类型**：`A | B`，满足其中一种即可

</details>

### Q9: 浏览器从输入 URL 到页面渲染的完整过程？

- **类别**: 浏览器原理
- **难度**: 中等
- **频率**: 极高

<details>
<summary>答题要点</summary>

**完整流程**：

1. **URL 解析与 DNS 解析**
   - 浏览器解析 URL 协议、域名、路径
   - DNS 域名解析：浏览器缓存 → 系统缓存 →  hosts 文件 → 本地 DNS → 根 DNS → 顶级域 DNS → 权威 DNS

2. **TCP 连接（三次握手）**
   - SYN → SYN+ACK → ACK，建立可靠连接
   - HTTPS 还需 TLS 握手（证书验证、密钥协商）

3. **发送 HTTP 请求**
   - 构建请求行、请求头、请求体
   - 浏览器发送请求到服务器

4. **服务器响应**
   - 返回状态码、响应头、响应体（HTML）

5. **浏览器解析渲染**
   - **解析 HTML** → 构建 DOM 树
   - **解析 CSS** → 构建 CSSOM 树
   - **合并** → 生成 Render 树（布局树）
   - **Layout（回流/重排）** → 计算元素位置和大小
   - **Paint（重绘）** → 绘制像素到图层
   - **Composite（合成）** → 多个图层合成显示

6. **JS 执行**
   - 遇到 script 标签暂停解析，下载并执行 JS
   - JS 可能修改 DOM/CSS，触发重排重绘

**关键优化点**：
- 减少 DNS 查询：DNS 预解析
- 减少 TCP 连接：HTTP 长连接、HTTP/2 多路复用
- 减少重排重绘：批量修改 DOM、使用 transform 动画
- 关键渲染路径优化：CSS 放头部、JS 放底部或加 defer/async

</details>

### Q10: 前端性能优化有哪些方法？从加载到渲染全链路？

- **类别**: 性能优化
- **难度**: 中等
- **频率**: 极高

<details>
<summary>答题要点</summary>

**一、网络加载优化**
- 减少 HTTP 请求：合并资源、雪碧图、代码分割
- 减小资源体积：压缩（gzip/brotli）、Tree Shaking、图片压缩
- CDN 加速：静态资源放 CDN，就近访问
- 缓存策略：强缓存 + 协商缓存，合理设置 Cache-Control
- 预加载：preload 关键资源、prefetch 下一页面资源
- DNS 预解析：`<link rel="dns-prefetch">`

**二、渲染性能优化**
- 减少重排重绘：批量修改 DOM、使用 transform/opacity 动画
- 防抖节流：滚动、resize、input 等高频事件
- 虚拟列表：长列表只渲染可视区域
- 懒加载：图片懒加载、组件懒加载、路由懒加载
- Web Worker：复杂计算放子线程，不阻塞主线程

**三、JavaScript 优化**
- 减少作用域链查找，避免频繁访问深层对象
- 合理使用 requestAnimationFrame
- 避免内存泄漏：清除定时器、移除事件监听、解绑闭包引用
- 代码分割 + 按需加载：路由级、组件级

**四、CSS 优化**
- 避免通配符选择器和深层嵌套
- 减少重排属性的使用（top/left → transform）
- will-change 提升为独立图层（不可滥用）
- 压缩 CSS，移除未使用样式（PurgeCSS）

**五、Vue/React 专项**
- v-show 替代 v-if（频繁切换）
- key 正确使用，避免就地复用
- 计算属性缓存、v-once、v-memo
- React：memo、useMemo、useCallback 合理使用
- 避免不必要的重渲染

**性能监控**：Lighthouse、Performance API、Web Vitals（LCP/FID/CLS）

</details>

### Q11: 前端工程化工具有哪些？Vite 比 Webpack 快的原因？

- **类别**: 工程化
- **难度**: 中等
- **频率**: 高

<details>
<summary>答题要点</summary>

**工程化工具分类**：
- **打包构建**：Webpack、Rollup、Vite、esbuild、Turbopack
- **代码规范**：ESLint、Prettier、Stylelint、Husky + lint-staged
- **包管理**：npm、yarn、pnpm
- **CI/CD**：GitHub Actions、Jenkins、GitLab CI
- **脚手架**：Vue CLI、Create React App、Vite 脚手架
- **Monorepo**：pnpm workspace、Turborepo、Lerna

**Vite 比 Webpack 快的原因**：

1. **开发服务器启动方式不同**
   - Webpack：需要先打包所有模块，再启动 dev server（冷启动慢）
   - Vite：利用浏览器原生 ESM，不需要打包，按需编译

2. **按需编译**
   - Webpack：全部打包到内存中
   - Vite：浏览器请求哪个模块才编译哪个模块，启动极快

3. **HMR 差异**
   - Webpack：修改一个文件，整个模块链重新打包
   - Vite：只需要让浏览器重新请求修改的模块，HMR 速度与项目规模无关

4. **底层构建工具**
   - Vite 开发环境用 esbuild 预构建依赖（Go 编写，比 JS 快 10-100 倍）
   - 生产环境用 Rollup（生态成熟、打包质量高）

**Webpack 的优势**：
- 生态更成熟，插件更丰富
- 对复杂项目的配置和优化更灵活
- 兼容性更好（支持 CommonJS / AMD / ESM）

**选型建议**：新项目优先 Vite，老项目继续 Webpack；大型复杂项目评估迁移成本。

</details>

### Q12: 跨域是什么？如何解决跨域问题？

- **类别**: 浏览器安全/网络
- **难度**: 中等
- **频率**: 极高

<details>
<summary>答题要点</summary>

**跨域**：浏览器的同源策略限制，协议、域名、端口三者有一个不同即为跨域。跨域时请求可以发出，但浏览器会拦截响应。

**同源策略限制**：
- Cookie、LocalStorage、IndexedDB 无法读取
- DOM 无法获取
- AJAX 请求被拦截（实际发出了，只是浏览器不展示结果）

**解决方案**：

1. **CORS（跨域资源共享）**
   - 服务端设置响应头：`Access-Control-Allow-Origin`
   - 简单请求：GET/POST/HEAD，直接发
   - 复杂请求：先发 OPTIONS 预检请求，通过后再发实际请求
   - 带 cookie 需设置 `withCredentials: true` 和 `Access-Control-Allow-Credentials: true`

2. **JSONP**
   - 利用 `<script>` 标签不受同源策略限制
   - 只能发 GET 请求，需要服务端配合
   - 现在基本不用了

3. **代理服务器**
   - 开发环境：Webpack/Vite 的 devServer proxy
   - 生产环境：Nginx 反向代理
   - 原理：浏览器 → 同源代理 → 目标服务器，绕过浏览器同源策略

4. **其他方案**
   - postMessage：窗口间通信
   - WebSocket：不受同源策略限制
   - document.domain + iframe：同主域不同子域
   - Nginx 反向代理：生产环境最常用

</details>

### Q13: 浏览器缓存策略？强缓存和协商缓存？

- **类别**: 浏览器原理/性能
- **难度**: 中等
- **频率**: 高

<details>
<summary>答题要点</summary>

**浏览器缓存**：浏览器将请求过的资源存储在本地，下次请求时直接使用缓存，减少网络请求。

**强缓存（不发请求，直接用缓存）**：
- 命中条件：缓存未过期
- 状态码：200（from memory cache / from disk cache）
- 相关响应头：
  - `Expires`：HTTP/1.0，绝对时间，受客户端时间影响
  - `Cache-Control`：HTTP/1.1，优先级更高
    - `max-age=3600`：缓存有效期（秒）
    - `no-cache`：不使用强缓存，需要协商验证
    - `no-store`：不缓存任何内容
    - `public/private`：是否允许代理服务器缓存

**协商缓存（发请求验证，服务器决定用缓存）**：
- 强缓存失效后，浏览器发送请求，由服务器判断是否使用缓存
- 命中返回 304 Not Modified，不返回资源体
- 未命中返回 200 和新资源
- 相关响应头：
  - `Last-Modified / If-Modified-Since`：文件最后修改时间
    - 缺点：精度只到秒、文件修改但内容没变也会失效
  - `ETag / If-None-Match`：文件内容的唯一标识（哈希）
    - 优先级高于 Last-Modified
    - 更准确，服务器计算有性能开销

**缓存优先级**：Cache-Control > Expires > ETag > Last-Modified

**缓存策略建议**：
- HTML：no-cache，每次协商验证
- JS/CSS/图片：强缓存 + 文件名 hash（内容变化则 hash 变，触发新请求）
- 频繁更新的资源：短 max-age + 协商缓存

</details>

### Q14: 前端安全问题有哪些？XSS 和 CSRF 原理和防护？

- **类别**: 前端安全
- **难度**: 中等
- **频率**: 高

<details>
<summary>答题要点</summary>

**XSS（跨站脚本攻击）**：
- **原理**：攻击者在页面注入恶意脚本，用户访问时执行，盗取 cookie 或篡改页面
- **类型**：
  - 存储型：恶意脚本存入数据库，所有访问用户都中招（最危险）
  - 反射型：恶意脚本在 URL 中，需诱导用户点击
  - DOM 型：前端 JS 直接解析用户输入并插入 DOM
- **防护**：
  - 输入过滤：对用户输入进行转义和过滤
  - 输出编码：HTML 转义（& < > " ' /）
  - HttpOnly Cookie：JS 无法读取 cookie
  - CSP（内容安全策略）：限制可执行脚本的来源
  - 使用框架（Vue/React）默认会转义，v-html/dangerouslySetInnerHTML 需谨慎

**CSRF（跨站请求伪造）**：
- **原理**：攻击者诱导用户登录后访问恶意网站，利用用户已登录状态，冒用身份发起请求
- **条件**：用户已登录目标网站、用户访问了恶意站点、目标站点没有 CSRF 防护
- **防护**：
  - Token 验证：每次请求携带 CSRF Token（存在 localStorage 或 form 中）
  - SameSite Cookie：设置 `SameSite=Strict/Lax`，限制第三方请求携带 cookie
  - 验证 Referer：检查请求来源域名
  - 关键操作加二次验证（短信、密码）

**其他安全问题**：
- **点击劫持**：iframe 覆盖透明层诱导点击 → X-Frame-Options: DENY
- **SQL 注入**：后端问题，前端做输入校验配合
- **中间人攻击**：HTTP 明文传输 → 使用 HTTPS
- **上传漏洞**：文件类型校验、重命名、存独立域名

</details>

### Q5: React 和 Vue 的区别？怎么选型？

- **类别**: 框架对比
- **难度**: 中等
- **频率**: 高

<details>
<summary>答题要点</summary>

**核心区别**：
| 维度 | React | Vue |
|------|-------|-----|
| 设计理念 | 函数式编程，JSX，一切皆 JS | 渐进式，模板语法，关注易用性 |
| 数据流向 | 单向数据流 | 单向数据流 + v-model 双向绑定语法糖 |
| 响应式 | setState 不可变更新，整棵子树重渲染 | Proxy 数据劫持，精确更新依赖组件 |
| 渲染优化 | 手动优化（memo/useMemo/useCallback） | 自动优化（编译时标记静态节点） |
| 模板语法 | JSX（JS 中写 HTML） | SFC 单文件组件（HTML/CSS/JS 在一起） |
| 学习曲线 | 较陡（JSX + Hooks + 状态管理） | 平缓（模板语法接近原生 HTML） |
| 生态 | 更丰富，React Native、Next.js 强大 | 也很丰富，Vite + Vue3 体验很好 |
| 灵活性 | 更高，自由度大 | 更规范，约定大于配置 |

**选型建议**：

- **选 Vue**：
  - 团队前端基础一般，需要快速上手
  - 中小型项目、后台管理系统
  - 喜欢模板语法和清晰的约定
  - 国内生态丰富，中文文档完善

- **选 React**：
  - 大型复杂项目，需要高度灵活的架构
  - 移动端跨平台需求（React Native）
  - 团队有较强的 JS 功底
  - 国际化项目，海外生态更好
  - SSR/SSG 需求强（Next.js 生态领先）

**总结**：两者都是优秀的框架，没有绝对的优劣，根据团队和项目特点选择。中小项目 Vue 开发效率高，大型复杂项目 React 更灵活可控。

</details>
