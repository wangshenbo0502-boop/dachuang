# 后端开发工程师简历模板与范例

## 一、推荐简历结构

> 遵循 **一页纸原则**，核心模块突出，技术细节量化。

| 序号 | 模块 | 重要性 | 建议篇幅 |
|------|------|--------|----------|
| 1 | 基本信息 | 必备 | 1 行 |
| 2 | 教育背景 | 必备 | 3-5 行 |
| 3 | 技术能力 | 核心 | 10-15 行 |
| 4 | 项目经历 | 核心（最重要） | 简历的 50% 以上 |
| 5 | 实习经历 | 加分项（有则优先放） | 5-8 行/段 |
| 6 | 竞赛获奖 | 加分项 | 3-5 行 |
| 7 | 校园经历/自我评价 | 可选 | 3 行以内 |

> **模块排序建议**：有实习经历则放在项目经历之前，无实习则项目经历紧跟技术能力。

## 三、项目经历书写模板（STAR法则）

> 后端项目要突出**技术深度**和**量化结果**，避免"参与开发"这类模糊描述。

### 模板框架

```
【项目名称】（项目类型/角色） | 时间
- S（背景）：一句话说明项目背景和目标
- T（任务）：你在项目中承担的职责和核心任务
- A（行动）：你具体做了什么技术实现（2-3条，要有技术细节）
- R（结果）：取得了什么效果（尽量量化，用数据说话）
```

### 填写示例（反面 vs 正面）

| 反面示例（太笼统） | 正面示例（STAR+量化） |
|---------------------|------------------------|
| 参与了秒杀系统的开发，用了 Spring Boot 和 Redis | 设计并实现高并发秒杀系统，基于 Redis + Lua 脚本实现原子扣减库存，1万并发下压测接口响应时间从 1200ms 降至 180ms，零超卖 |
| 做了一个权限管理系统 | 基于 RBAC 模型实现企业级权限管理系统，使用 Spring Security + JWT 做认证授权，接入 Redis 缓存后权限校验耗时从 300ms 降至 15ms |
| 优化了数据库查询性能 | 对订单表建立联合索引并优化慢 SQL，单表 500 万数据下查询耗时从 3s 降至 200ms，提升 15 倍 |

## 四、技术能力书写技巧

### 4.1 按熟练程度分层

**推荐分级**：精通 > 熟练 > 熟悉 > 了解

> 原则：**"精通"不超过 2 个**，"熟练"是你面试主要被问的内容，一定要真实。

### 4.2 突出关键词匹配 JD

1. **从 JD 中提取高频词**：例如 JD 中反复提到"微服务"，就在简历中多次出现这个词
2. **技能顺序按 JD 排序**：JD 中先列的技能，你也放在前面
3. **不要堆砌无关技能**：求职后端就不要写"精通 Photoshop"

### 4.3 后端简历高频关键词

`Java` `Spring Boot` `Spring Cloud` `MySQL` `Redis` `消息队列` `微服务` `分布式` `高并发` `JVM调优` `数据库优化` `Docker` `Kubernetes`

## 七、常见问题 FAQ

**Q：后端简历一定要放 GitHub 吗？**
A：最好有。没有 GitHub 至少要有一个可展示的项目链接。空的 GitHub 不如不放。

**Q：项目经历写几个合适？**
A：2-3 个精品项目，每个写 3-5 个要点。宁精勿滥，不要把课程大作业都堆上去。

**Q：没有实习经历怎么办？**
A：用高质量的个人项目、开源贡献、实验室项目来弥补。项目质量比数量重要。

**Q：技能栏里"了解"的技能要不要写？**
A：可以写，但放在最后。面试时如果被问到"了解"级别的技能，坦诚说了解即可。
