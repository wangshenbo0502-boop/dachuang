# 大学生职业能力证据卡建设指南

职业能力数字孪生不是一份更长的简历，而是用户职业事实的结构化、可追溯表示。它要回答三个问题：候选人会什么、在哪件事中使用过、有什么材料可以证明。能力证据卡是这一表示的最小单元，可被岗位匹配、简历定制、面试问答和成长规划重复使用，同时避免不同模块各自编造经历。

## 一、证据卡的基本结构

每张证据卡对应一个清晰能力或一次可复用成果，不要把整个大学经历塞入一张卡。推荐字段如下：

| 字段 | 说明 |
|---|---|
| `capability` | 能力名称，如需求分析、Java 服务开发 |
| `context` | 发生场景，如课程设计、实习、竞赛 |
| `action` | 用户本人完成的动作 |
| `result` | 可核验产出或影响，不强制要求数字 |
| `evidence` | 仓库、文档、证书、演示、导师确认等 |
| `role_scope` | 个人职责及团队边界 |
| `time_range` | 起止时间或完成日期 |
| `proficiency` | 由证据支持的熟练度描述 |
| `verification` | 已验证、用户声明、待验证、过期 |
| `sensitivity` | 是否含隐私、商业秘密或受限材料 |
| `source_record` | 原始经历或文件的引用标识 |

能力名称应采用“可执行动作 + 对象”或行业通用术语，如“使用 SQL 完成多表数据分析”，比“学习能力强”更适合检索。`action` 必须强调本人贡献；团队获得奖项并不自动证明每个成员完成了全部技术工作。

## 二、证据来源与强度分级

证据可来自课程作业、课程成绩、实验报告、项目仓库、提交记录、产品原型、演示视频、部署地址、竞赛材料、专利或论文、实习证明、公开作品和导师评价。系统可以帮助整理，但应允许用户屏蔽含个人信息、客户数据、源代码秘密或保密协议限制的材料。

可采用四级证据强度：

- **A 级：可独立验证。** 公开仓库、公开作品、可查证证书、正式发表成果或带时间记录的系统产出。
- **B 级：有原始材料。** 非公开报告、演示视频、截图、版本记录、学校或企业出具的材料，可在用户授权后查看。
- **C 级：有详细过程。** 用户能说明背景、本人动作、技术选择、问题和结果，但暂时缺少外部材料。
- **D 级：仅有自我声明。** “熟悉、精通、擅长”等结论，没有场景和产出支持。

等级用于提示证据充分程度，不等于给学生贴能力高低标签。一个真实的 C 级证据优于虚构数字包装出来的 A 级表述。系统也不应为了“好看”把课程接触自动提升为熟练掌握。

## 三、从经历提取证据卡

第一步是收集原始记录。让用户按课程、项目、竞赛、社团、科研、实习和个人作品分别列出材料，不要求一开始就写成简历语言。第二步识别任务：当时要解决什么问题、服务谁、交付什么。第三步划分贡献：哪些是本人完成，哪些是团队完成，哪些由导师或现有框架提供。第四步提取方法：使用了什么知识、工具和判断。第五步记录结果：优先使用可追溯成果，没有可靠数字时可写“完成上线、通过验收、被团队采用”，不要制造提升百分比。

以校园二手交易项目为例，弱描述是“负责后端，使用 Spring Boot”。较完整的证据卡可以写为：“在 4 人课程项目中负责商品发布和订单模块；设计接口与数据库表，完成参数校验、库存状态流转和接口测试；保留仓库提交记录、接口文档和演示视频。”它没有夸张的流量数字，却能支持后端开发、数据建模、接口设计和协作能力。

## 四、熟练度不能只由模型判定

熟练度应结合接触深度、使用频率、独立程度、问题复杂度和证据新鲜度。推荐采用描述性等级：了解概念、在指导下完成、可独立完成、可处理复杂问题、可指导他人。每个等级必须展示依据，并允许用户降级或纠正。

大模型可以提出候选能力标签，但不得仅凭一个工具名推断所有相邻技能。例如使用过 Pandas 不必然代表掌握统计推断；完成 Vue 页面不必然代表掌握前端性能优化。系统遇到推断时应标记为“候选能力”，等待用户确认或补充材料后再转为正式证据卡。

## 五、证据卡与岗位、简历、面试的联动

岗位解析后，每条要求应检索最相关的证据卡，并返回证据强度和时间。简历生成只允许从已确认卡片中选材；若没有证据，应建议补充经历或学习计划，而不是生成一段看似合理的虚假项目。面试准备可根据同一证据卡追问背景、决策、困难、协作和复盘，保证简历与口述一致。

一次投递后，系统应保存“岗位要求—使用的证据卡—简历句子”的关系。用户修改原始证据时，不宜静默篡改已投递版本，而应创建新版本，并提示历史申请曾使用旧信息。这样才能实现真正的材料可追溯。

## 六、隐私、过期与撤回

证据卡可能含姓名、联系方式、学校记录、企业内部信息和作品链接。默认应最小化展示，敏感附件与公开文字分开存储。用户必须能够导出、修改、删除或撤回某张卡；已删除证据不应继续被新简历检索使用。证书有效期、技术栈使用时间和链接可访问性需要定期复查，过期资料应标注而不是自动删除历史。

对第三方大模型传输材料前，应去除与任务无关的身份证号、住址、电话、私人邮箱、访问令牌和企业秘密。模型输出中的新增事实要经过差异检查：凡是原始证据卡不存在的公司、角色、奖项、证书、时间和数字，一律视为待确认内容。

## 七、质量检查

- 一张卡是否只描述一个主要能力或成果；
- 是否区分个人贡献与团队成果；
- 是否有原始材料或清晰过程支撑；
- 数字、日期、奖项和证书能否回到来源；
- 是否把候选推断与用户确认事实分开；
- 是否标记隐私等级、有效期和验证状态；
- 是否能被岗位匹配、简历和面试模块共同引用；
- 用户是否可以纠错、撤回和查看历史版本。
