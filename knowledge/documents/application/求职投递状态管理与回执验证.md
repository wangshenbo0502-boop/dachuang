# 求职投递状态管理与回执验证

求职助手最容易出现的逻辑错误，是把“执行了点击动作”当成“投递成功”。实际页面可能因为网络、会话、必填项、验证码或岗位关闭而失败，也可能已经成功但没有明显跳转。可信系统必须用状态机管理申请，并保存足以复核的回执证据。

## 一、投递记录的最小对象

每次申请应创建唯一记录，至少包含：岗位快照标识、企业和岗位名称、原页面地址、页面抓取时间、用户标识、使用的简历及附件版本、证据卡版本、创建时间、当前状态、状态更新时间和回执证据。岗位网页可能更新或下线，历史记录必须引用当时快照，不能只保留当前链接。

一份简历可能用于多个岗位，一个岗位也可能重新开放，因此不能只用“企业 + 岗位名”去重。推荐将企业主体、岗位标识、地点、招聘批次、页面地址和首次发现时间综合生成候选指纹，再由用户判断是否属于重复申请。

## 二、推荐状态机

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| `saved` | 已收藏岗位，尚未准备材料 | 解析、放弃 |
| `eligibility_check` | 正在核对硬条件 | 准备材料、需补充、放弃 |
| `materials_ready` | 材料已生成并确认 | 开始预填 |
| `prefilling` | 正在填写页面 | 待人工确认、失败 |
| `awaiting_user_submit` | 预填完成，等待用户提交 | 已点击提交、取消 |
| `verification_pending` | 已执行提交但结果未确认 | 成功、失败、未知 |
| `submitted` | 有充分回执证明已提交 | 测评、面试、结束 |
| `failed` | 明确失败且未提交 | 修复后重试、结束 |
| `withdrawn` | 用户主动撤回或放弃 | 结束 |

后续招聘进展可作为独立阶段记录，如简历筛选、笔试、测评、一面、二面、HR 面、录用、拒绝或用户终止。不要把“长时间无消息”自动改为“拒绝”，可以标记为“无更新”并记录最后核验时间。

## 三、什么可以证明投递成功

较强证据包括：页面明确显示成功并包含岗位信息；系统生成申请编号或回执编号；招聘平台的申请记录新增对应条目；企业或平台发送包含岗位信息的确认邮件；用户人工确认并上传成功截图。单一证据不一定永久可靠，系统应同时保存文本摘要、时间和来源类型。

仅发生以下事件不能单独判定成功：触发了按钮点击；浏览器地址变化；页面关闭；接口返回无法解释的通用状态；按钮变灰；插件脚本没有报错。系统可以把这些记录为操作事件，但当前状态仍应是 `verification_pending`。

确认邮件解析应遵循最小化原则，只处理用户授权的邮件或转发内容，不应要求读取整个邮箱。抽取企业、岗位、时间和申请编号后，让用户确认匹配关系。邮件中的链接要作为外部内容处理，不能自动登录或执行后续操作。

## 四、材料版本和审计链

投递记录必须冻结当时使用的材料版本，包括简历正文哈希、文件名、生成时间、目标岗位和用户确认时间。若用户之后修改同名文件，历史记录仍指向旧版本。这样用户在面试前可以准确查看“当时向这家企业说了什么”。

审计链记录关键事件即可：岗位解析完成、用户修正硬条件、材料生成、事实校验、用户确认、开始预填、用户点击提交、检测到回执、状态变更。日志应记录事件类型和必要标识，不保存密码、验证码、完整证件号码或页面中的无关个人信息。

## 五、防止重复申请

开始新申请前，系统搜索相似历史记录，并提示同企业、同岗位、同招聘批次的已有状态。若已有 `submitted` 记录，默认阻止再次预填，用户确认这是不同岗位编号或允许重复申请后才能继续。若上一条为 `failed`，应先展示失败原因和当时材料版本。

招聘网站可能允许更新简历而不是重新投递。系统不能假定所有平台规则相同，应提示用户查看平台说明。对于“结果未知”的记录，应优先核验申请列表和确认邮件，而不是直接重试。

## 六、状态真实性与用户纠错

所有状态变更都要区分来源：页面检测、邮件回执、平台申请记录、用户手动标记或系统推断。系统推断不能覆盖用户确认，也不能把概率展示成事实。如果用户发现岗位名称识别错误，可以修正记录，同时保留原快照和修改原因。

面试邀请、拒绝通知和录用信息同样需要来源。没有明确通知时，系统可以提醒用户跟进，但不生成“企业已拒绝”等结论。对含有敏感信息的回执截图应提供遮盖、删除和到期清理功能。

## 七、看板与提醒

投递看板应按状态和时间展示，而不是用单一“投递数”鼓励海投。推荐指标包括：待确认申请、结果未知申请、即将截止岗位、等待测评、待准备面试、长时间无更新以及需要人工跟进的事项。用户可以设置提醒频率和静默时间。

复盘统计只使用已验证状态。例如“已投递岗位数”只统计 `submitted`，点击但未核验的记录单列。邀约率的分母和时间窗口必须说明，样本很小时不应据此给出确定性策略。

## 八、检查清单

- 是否把点击、提交中和提交成功分开；
- 是否保存当时的岗位快照和材料版本；
- 是否至少用一种强证据确认成功；
- 状态未知时是否避免自动重试；
- 是否识别同岗位重复申请；
- 状态是否标明来源和最后核验时间；
- 是否允许用户修正且保留修改记录；
- 日志和回执是否经过隐私最小化处理。
