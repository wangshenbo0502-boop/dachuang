# 招聘者角色与站内招聘设计书

日期：2026-09-30。依据：用户要求先完成计划书再工作，全权负责，新增招聘者角色及其功能，保持技术栈和前端风格，禁止使用子智能体。

## 现状与目标

系统已有 QQ 邮箱验证码注册、Argon2 密码、JWT 登录、学生档案与简历版本，以及基于知识库的岗位方向匹配和 BOSS 外部投递助手。目前 Account 没有角色，登录后必须加载学生档案。

本轮实现学生与招聘者两个角色，形成企业资料维护、招聘岗位管理、学生站内投递、招聘者处理简历、学生跟踪反馈的业务闭环。

## 方案与边界

采用现有账号新增 `role` 字段，增加 `recruiter_profiles`、`recruitment_jobs`、`recruitment_applications` 业务表。沿用 Vue 3、TypeScript、Vite、Pinia、Element Plus、FastAPI、SQLAlchemy、Pydantic；不引入依赖，不替换业务数据库或 PostgreSQL/pgvector 知识库，不改配色、全局样式与布局。

只增加按钮无法落实服务端权限，独立后台会重复现有登录和布局，因此选择现有应用内按角色显示导航和页面的方案。

注册时可选择学生或招聘者，默认学生。已注册账号迁移为学生；不提供前端修改角色接口。JWT 只用于识别账号，角色和归属均从数据库读取。为兼容既有非空 `profile_id`，招聘者注册仍建立基础身份记录，招聘者的业务资料单独保存；不向招聘者开放学生档案、AI分析、简历和外部投递 API。

招聘者拥有专用工作台：岗位管理、收到的投递、企业资料。学生新增招聘岗位与站内投递入口，保留原有工作台、岗位知识匹配和 BOSS 投递功能。系统设置显示正确角色。登录、刷新、直接访问与重定向均根据服务端角色处理。

## 招聘业务

- 企业资料：企业名称、行业、城市、简介、联系人、联系邮箱；为空时提示补充，发布前企业名称、联系人、有效联系邮箱必须齐全。企业资料为自行填写，界面不得宣称已认证。
- 岗位：标题、方向分类、城市、薪资说明、用工类型、学历要求、经验要求、职责、任职要求、技能标签。新建为草稿；仅完整岗位可发布。已发布岗位需先下架才能编辑，避免在线内容在编辑中变化。
- 状态：`draft` 草稿、`published` 招聘中、`closed` 已下架。草稿/已下架可发布；招聘中可下架；仅无投递且非招聘中的记录可以删除。发布前校验标题、分类、城市、薪资、职责、要求、企业资料。学生仅能读取招聘中岗位；下架后旧详情链接返回 404，既有投递仍保留岗位和企业快照。
- 学生可按关键词、分类和城市分页查看招聘岗位，查看岗位与企业说明。投递必须选择本人已有简历版本并主动确认分享，可附求职说明。
- 投递保存当时的岗位、企业和简历快照；简历只包含该版本选择的技能、项目、竞赛和实习以及概要、基本联系方式，不分享整份就业档案、AI会话或分析历史。后续修改档案或简历不改变已投递内容。
- 同一学生对同一岗位只能投递一次，数据库唯一约束防止重复提交；下架岗位不可投递；学生可撤回未结束的投递。
- 招聘者仅能查看自己岗位收到的简历并更新处理状态和给学生的反馈。状态为 `submitted` 已投递、`reviewing` 筛选中、`interview` 面试中、`offered` 已录用、`rejected` 未通过、`withdrawn` 已撤回。已录用/未通过/已撤回不可再变更；不允许跳回已投递，不允许招聘者设置撤回状态。反馈只是站内记录，不声称发送了邮件或自动安排面试。

## 权限与异常

未登录返回 401，错误角色返回 403，他人的招聘记录按 404 处理。账号、岗位所有者、学生所有者和简历归属一律由服务端获取，拒绝客户端额外字段，避免篡改归属与状态。学生 API 统一增加角色验证，招聘者 API 统一检查角色与记录所有权。

页面复用 PageHeader、SectionPanel、StateView、job-card、filter-bar 等已有组件与类。显示真实的加载、失败、空态和数量；表单保存失败保留输入；发布、下架、删除、投递、撤回均有清晰确认；提交期间防重复点击。移动端沿用现有侧栏机制，新增局部布局适配窄屏。

## 验收

1. 原学生账号兼容迁移，注册默认学生；招聘者注册、登录、刷新后进入招聘工作台。
2. 学生不可调用招聘管理接口；招聘者不能调用学生私有接口；招聘者 A 不能查看或操作 B 的岗位和投递。
3. 完成企业资料、保存草稿、发布、学生检索并投递、招聘者查看快照并反馈、学生查看反馈、下架；空库保持空态。
4. 非本人简历、重复投递、下架岗位投递、非法状态流转、删除已有投递岗位、在线编辑均被拒绝。
5. 前端类型检查和生产构建通过，后端相关测试与既有业务回归通过；使用独立测试库，避免触碰现有业务数据。
6. 使用本机浏览器做真实页面操作，检查桌面和移动端布局，保存可复查截图与验证报告。外部 AI、QQ SMTP、BOSS 和 pgvector 不纳入本轮新功能验收，不以模拟结果声称这些服务通过。
