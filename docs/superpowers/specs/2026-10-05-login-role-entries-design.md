# 招聘者与求职者登录入口设计

用户需求：优化登录，清晰展示“招聘者登录”和“求职者登录”。

## 现状与方案

现有 Vue 登录页只有一个通用表单，账号和路由已支持 `student`、`recruiter` 两种角色。保留当前深色品牌区域、蓝色主按钮及 QQ 邮箱密码认证。

采用同页双身份卡片：两个入口同时可见，共享邮箱密码表单，当前身份有明确选中状态。相比两份独立登录页，这个方案避免重复维护，切换也更直接；相比普通下拉框，两个角色无需展开即可看见。

## 页面与导航

- 默认展示求职者登录；两个入口使用“求职者登录”“招聘者登录”。
- 切换身份后，品牌文案、表单标题、按钮及注册文案随之变化，保留已输入的邮箱和密码，并清除旧错误。
- 使用 `/login?role=student`、`/login?role=recruiter` 表示入口，刷新、前进和后退保持一致。未指定有效身份时，根据受保护的招聘者目标地址判断角色，否则默认求职者。
- 注册链接携带当前角色，注册页自动选中对应身份；返回登录携带注册页当前选中的角色。
- 忘记密码与重置成功后的返回登录保留身份和原目标地址。
- 登录成功仍通过既有 `safeInternalRedirect` 校验目标地址，招聘者进入 `/recruiter`，求职者进入 `/dashboard`，同角色的安全原目标地址继续保留。
- 手机布局中两个入口和表单不横向溢出，角色按钮支持键盘操作及选中状态的辅助技术表达。

## 认证边界

登录请求增加可选 `role: student | recruiter`。浏览器始终提交所选身份，服务端先验证邮箱密码和账号状态，再校验请求身份是否与数据库账号一致。错选身份返回明确提示，不签发新 token，不更新登录时间。旧客户端不提交角色时，仍按真实账号角色登录。

`student` 为既有内部角色值，页面称“求职者”，不修改账号数据、业务权限或数据库结构。

## 验证

针对性认证测试覆盖正确身份、两种错选、错误密码优先、非法角色、旧请求兼容及会话行为。前端执行包含 TypeScript 校验的生产构建。使用临时 SQLite 与独立端口完成真实浏览器登录、角色切换、注册预选、密码恢复导航、原地址跳转与窄屏检查，并保存截图和结果。测试不访问既有业务数据库，不发送真实邮件。
