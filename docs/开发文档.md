## 2. 开发人员职责边界

### 2.1 前端负责人

**负责**：

- 3D 场景与交互开发（`frontend/src/components/canvas/**`：房间、走廊、传送、着色器）；
- 全局 UI 与弹层（`frontend/src/components/ui/**`：NavigationUI、GlobalOverlay、ProfileOverlay、JobMatchPanel 等）；
- API Client 封装（`frontend/src/api/*.ts`，统一走 `@/api/index.ts` 的 axios 实例）；
- 状态管理（`frontend/src/context/**`：User/JobMatch/Scene/Audio/Performance/Achievements）与数据适配（`src/adapters/**`）；
- 数据展示与错误提示；
- 前端自测（含 SSE 流式页面，接线后）。

**不得**：

- 修改后端业务逻辑或数据库；
- 根据猜测定义接口字段——一切以 [02-API接口文档](./02-API接口文档.md) 为准，发现文档与实际不符时先反馈后端确认，再更新文档；
- 在前端实现核心业务算法（如匹配评分计算——由后端 `/api/match` 返回）；
- 在组件内硬编码 `http://localhost:8000` 等绝对地址。

### 2.2 后端负责人

**负责**：

- FastAPI 接口（`app/api/`）与请求/响应模型（`app/schemas/`）；
- 数据库设计与 ORM 模型（`app/models/`）；
- Service 层业务逻辑（`app/services/`）；
- AI 模块封装与调用（`app/ai/`，见 [04](./04-AI模块设计文档.md)）；
- 知识库检索接入（`app/knowledge/`，见 [05](./05-RAG知识库设计文档.md)）；
- 后端测试（集成测试 + E2E 冒烟）。

**不得**：

- 为适配前端临时返回非规范字段（响应必须走 `utils/response.py` 的三段式）；
- 把业务逻辑写进 API 层（API 层只做参数接收 → 调 Service → 组装响应）；
- 绕过 `DeepSeekClient` / `KnowledgeService` 直接访问 AI 或知识文档；
- 修改接口契约而不先更新 02 文档（见第 6 章变更流程）。

### 2.3 前后端协作约定

1. 接口字段疑问 → 查 02 文档 → 仍不明确 → 由后端在文档中补充说明，前端**不猜**。
2. 需要新接口 → 前端提需求（说明页面用途与期望数据）→ 后端按第 3 章流程先更新 02 → 再实现。
3. 联调问题先通过 `X-Request-ID` 对账日志（见 6.3 节）定位责任侧，不互相甩锅。

### 2.4 AI 辅助开发的角色定位

ChatGPT / Claude Code / Cursor / Copilot 等 AI 工具**只能作为开发辅助**，不能替代架构设计、业务判断与代码审核。协作细则见第 11 章；核心原则见 [01 第 15 章](./01-项目开发说明书.md)。

## 3. 标准开发流程

### 3.1 整体流程

所有功能（无论大小）按以下顺序推进，**禁止先写代码再补接口文档**：

```text
① 需求确认
   ↓  产出：明确的用户操作 / 系统输出 / AI 参与环节
② 接口设计（契约先行）
   ↓  产出：更新 02 文档（URL、方法、参数、返回、错误码）
③ 数据库设计（如涉及）
   ↓  产出：更新 03 文档（表、字段、关系）
④ 后端实现
   ↓  产出：Model → Schema → Service → API → main.py 注册 → 集成测试
⑤ 后端自测
   ↓  产出：Swagger 全路径走通 + 回归测试通过
⑥ 前端开发
   ↓  产出：页面 + API 封装（只依据 02 文档）
⑦ 前后端联调（见第 6 章）
   ↓  产出：联调问题清单清零，文档同步
⑧ 系统测试与验收
   ↓  产出：满足 01 第 12.2 节 DoD + 第 10 章性能基线
⑨ 版本发布
      产出：版本号按 01 第 12.1 节规则递增，变更记录入文档
```

### 3.2 各阶段要点

| 阶段 | 要点 | 禁止事项 |
|------|------|---------|
| ① 需求确认 | 用一句话写清：用户做什么、系统返回什么、AI 在哪个环节参与 | 需求未确认就动手 |
| ② 接口设计 | 确定 URL / 方法 / 请求参数 / 返回结构 / 错误处理；规划接口须标 `规划/待实现` | 先写代码再补文档 |
| ③ 数据库设计 | 遵循 [03 第 1.3 节](./03-数据库设计文档.md)设计原则；新表需在 `models/__init__.py` 导出 | 把 Prompt/临时数据写入数据库 |
| ④ 后端实现 | 严格按 4.1 节顺序与分层边界 | 跨层调用、跳过 Service |
| ⑤ 后端自测 | `/docs` 走通完整路径；`test_job_match.py` + 用户模块测试回归通过 | 只测正常路径 |
| ⑥ 前端开发 | 只按 02 文档调用；SSE 页面同步实现 | 猜字段、硬编码 URL |
| ⑦ 联调 | 按 6.1 节流程；问题全部记录并归零 | 边联调边改契约不记录 |
| ⑧ 验收 | 对照 DoD 与性能基线逐项打钩 | 未验收就标"已完成" |

## 4. 后端开发实操指南

### 4.1 新增一个业务模块的完整步骤

以规划中的「岗位收藏」为例（真实规划项，见 [01 第 14 章](./01-项目开发说明书.md)），演示标准步骤。**顺序固定：Model → Schema → Service → API → 注册 → 测试 → 文档**。

#### 第 1 步：ORM 模型 `app/models/job_favorite.py`

```python
"""
文件名称：job_favorite.py
文件作用：定义用户岗位收藏的 ORM 数据模型。
"""

from __future__ import annotations

from datetime import datetime

from sqlalchemy import DateTime, ForeignKey, String, UniqueConstraint, func
from sqlalchemy.orm import Mapped, mapped_column

from app.database.connection import Base


class JobFavorite(Base):
    """用户收藏的岗位记录。"""

    __tablename__ = "job_favorites"
    __table_args__ = (UniqueConstraint("user_id", "job_id", name="uq_user_job"),)

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    user_id: Mapped[int] = mapped_column(
        ForeignKey("users.id", ondelete="CASCADE"), nullable=False, index=True
    )
    job_id: Mapped[str] = mapped_column(String(200), nullable=False)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, server_default=func.now()
    )
```

> ⚠️ 必须在 `app/models/__init__.py` 中导出新模型，否则 `init_db.py` 的 `create_all` 不会建表（见 [03 第 8 章](./03-数据库设计文档.md)）。

#### 第 2 步：Pydantic 模型 `app/schemas/job_favorite.py`

```python
"""
文件名称：job_favorite.py
文件作用：定义岗位收藏接口使用的 Pydantic 数据结构。
"""

from datetime import datetime

from pydantic import BaseModel, ConfigDict, Field


class JobFavoriteCreate(BaseModel):
    """收藏岗位请求体。"""
    user_id: int = Field(ge=1, description="用户ID")
    job_id: str = Field(min_length=1, max_length=200, description="知识文档岗位ID")


class JobFavoriteResponse(BaseModel):
    """收藏记录响应。"""
```

#### 第 3 步：业务服务 `app/services/job_favorite_service.py`

```python
"""
文件名称：job_favorite_service.py
文件作用：岗位收藏的查询与增删业务逻辑。
"""

from sqlalchemy import select
from sqlalchemy.exc import SQLAlchemyError
from sqlalchemy.orm import Session

from app.models.job_favorite import JobFavorite
from app.models.user import User
from app.schemas.job_favorite import JobFavoriteCreate
from app.utils.exceptions import ResourceNotFoundError


class JobFavoriteService:
    """岗位收藏领域的业务服务。"""

    def __init__(self, database_session: Session) -> None:
        self.database_session = database_session

    def add_favorite(self, data: JobFavoriteCreate) -> JobFavorite:
        """新增一条岗位收藏（重复收藏幂等返回已有记录）。"""
        self._get_user_or_raise(data.user_id)
        existing = self.database_session.scalar(
            select(JobFavorite).where(
                JobFavorite.user_id == data.user_id, JobFavorite.job_id == data.job_id
            )
        )
        if existing is not None:
            return existing
        favorite = JobFavorite(**data.model_dump())
        self.database_session.add(favorite)
        self._commit_and_refresh(favorite)
        return favorite

    def _get_user_or_raise(self, user_id: int) -> User:
        user = self.database_session.get(User, user_id)
        if user is None:
            raise ResourceNotFoundError("学生资料不存在")
        return user

    def _commit_and_refresh(self, instance) -> None:
        """提交事务并刷新实例（失败回滚后重抛）。"""
        try:
            self.database_session.commit()
            self.database_session.refresh(instance)
        except SQLAlchemyError:
            self.database_session.rollback()
            raise
```

#### 第 4 步：接口层 `app/api/job_favorite.py`

```python
"""
文件名称：job_favorite.py
文件作用：提供岗位收藏的 REST API。
"""

from typing import Any

from fastapi import APIRouter, Depends, Path, status
from pydantic import BaseModel
from sqlalchemy.orm import Session

from app.database.session import get_db
from app.schemas.job_favorite import JobFavoriteCreate, JobFavoriteResponse
from app.services.job_favorite_service import JobFavoriteService
from app.utils.response import success

router = APIRouter(prefix="/api/favorites", tags=["岗位收藏"])


@router.post("", status_code=status.HTTP_201_CREATED)
def add_favorite(
    data: JobFavoriteCreate, database_session: Session = Depends(get_db)
) -> dict[str, Any]:
    """收藏一个岗位。"""
    favorite = JobFavoriteService(database_session).add_favorite(data)
    response = JobFavoriteResponse.model_validate(favorite)
    return success(response.model_dump(mode="json"), message="收藏成功")
```

### 4.2 数据库会话与事务约定

| 约定 | 说明 |
|------|------|
| 会话获取 | 只通过 `Depends(get_db)` 依赖注入，请求结束自动关闭 |
| 提交位置 | 写操作统一在 Service 层 commit；API 层不碰事务 |
| 失败处理 | `SQLAlchemyError` → `rollback()` 后重抛（参考 `UserService._commit_and_refresh`） |
| N+1 防范 | 查聚合根用 `selectinload` 预加载关联（参考 `UserService._eager_load_options`） |
| 禁止 | 在请求外持有 Session；绕过 ORM 直接写 SQL 删用户 |

### 4.3 统一响应与异常使用规范

```python
# 成功（三段式，code=0）
from app.utils.response import success
return success(data, message="操作成功")

# 业务错误：在 Service 层抛自定义异常，API 层不捕获（交给全局处理器）
from app.utils.exceptions import ResourceNotFoundError
raise ResourceNotFoundError("学生资料不存在")
```

- 错误码只用 `utils/response.py` 的 `ErrorCode` 枚举，禁止魔法数字；
- 禁止裸 `raise Exception`；禁止自定义返回结构绕过 `success()/error()`；
- 唯一允许吞异常的场景：AI 增强逻辑静默降级（[01 第 10 章](./01-项目开发说明书.md)）。

### 4.4 AI 能力接入规范（新增 AI 功能时）

1. **调用入口**：`DeepSeekClient.instance().chat_json(messages, temperature=…)`，禁止自建 OpenAI 客户端；
2. **System Prompt**：新建 `knowledge/prompts/system_xxx.md`（外置，免重启），通过 `SystemPrompts.get(name, fallback)` 加载；
3. **用户数据**：进程内用 `UserService(db).get_user_context(user_id)`，禁止直查 ORM（[01 第 9.2 节](./01-项目开发说明书.md)）；
4. **知识增强**：需要岗位/技能知识时用 `KnowledgeService.instance().search(query, category, top_k)`；
5. **输出契约**：AI 必须返回结构化 JSON（Prompt 中写明字段），解析只走 `chat_json()`；
6. **降级设计**：增强类失败静默降级；核心分析失败向上抛异常；
7. **落库**：结果快照存对应记录表（含 `raw_result`），`is_mock` 标识透出给前端。

完整 Prompt 工程与四业务流程见 [04-AI模块设计文档](./04-AI模块设计文档.md)。

### 4.5 日志使用规范

- 模块级 logger：`logging.getLogger(__name__)`（全局日志配置见 `app/utils/middleware.py` 的 `configure_logging`）；
- 排查线上问题优先用 `X-Request-ID` 在请求日志中定位；
- **禁止记录**：密码、API Key、简历全文等敏感内容（见第 8 章）。

### 5.2 axios 实例与拦截器（已实现，`api/index.ts`）

现有实现要点（修改须保持行为一致）：

- `baseURL: "/api"`、`timeout: 30000`；请求拦截器注入 8 位 `X-Request-ID`；
- 响应拦截器将 AxiosResponse 解包为三段式 body（调用方 `res.data` 直接取业务数据）；
- `code !== 0` 统一抛 `ApiError`（携带 `code` 与 HTTP `status`）；422 时提取首条校验错误文案；429 给出友好提示；网络错误 `status=0`。

新增 AI 功能调用时可在单次请求覆盖超时（如 `startMatch` 用 `timeout: 60000`）。

### 5.3 API 模块编写规范（现状与规则）

`api/*.ts` 已按模块实现（user/analysis/jobMatch/resume/growth/system），其中 resume/growth/system 尚无组件消费。规则：

- 函数名用动词（`getJobList`、`startMatch`）；URL 只写 `baseURL` 之后的相对路径；
- 类型定义与 02 文档字段一一对应（`types.ts` 集中声明），禁止凭空增删；
- 中文 `job_id` 必须 `encodeURIComponent`；
- 消费方统一通过 Context（`UserContext`/`JobMatchContext`）取数，不在组件里裸调 axios。

### 5.4 SSE 流式消费（工具已实现，`utils/sse.ts`）

`streamSSE(path, body, handlers)` 已按 02 第 9 章事件契约实现（POST + fetch + ReadableStream，支持 start/chunk/complete/error 四类事件）。**当前无组件调用**；接线 AI 流式 UI 时直接复用：

```typescript
import { streamSSE } from "@/utils/sse";

streamSSE("/stream/analysis", { user_id: 1 }, {
  onStart: (msg) => { /* 显示"分析开始…" */ },
  onChunk: (text) => { /* 打字机追加文本 */ },
  onComplete: (result) => { /* 渲染完整 JSON 结果 */ },
  onError: (msg) => { /* 错误提示 */ },
});
```

事件契约见 [02 第 9 章](./02-API接口文档.md)。注意：流式结果**不落库**，需要历史记录时调用同步接口。

### 5.5 新增功能/房间流程

1. 3D 房间：`components/canvas/rooms/<Room>/` 新建组件（文件头中文注释），在 `Experience.jsx` 与走廊/传送配置中登记；
2. 弹层 UI：数据经 `adapters/` 转为 `OverlayPayload`，由 `GlobalOverlay` 按布局渲染（新增布局在 `GlobalOverlay.jsx` 注册）；
3. 跨组件状态：新建 Context（Provider 在 `App.jsx` 挂载）；
4. 只消费 `api/*.ts` 封装函数；错误经 `ApiError` 判断（`err.status === 0` 为网络错误）。

### 5.6 禁止事项

- ❌ 硬编码 `http://localhost:8000`（统一 `baseURL: "/api"` + Vite 代理/CORS）；
- ❌ 根据 Swagger 猜字段后自行命名（以 02 文档为准）；
- ❌ 以 HTTP 状态码判断业务成功（唯一标准 `code === 0`）；
- ❌ 用 EventSource 调 POST 流式接口；
- ❌ 前端直接读取 `knowledge/` Markdown（岗位知识一律走后端接口）；
- ❌ 用 `dangerouslySetInnerHTML` 渲染岗位 Markdown（统一走 `parseMarkdownLite` 轻量解析）。

## 6. 前后端联调规范

### 6.1 联调流程

```text
后端完成接口
  ↓
Swagger 自测通过（/docs 全路径走通）
  ↓
确认 02 文档已同步（字段/示例/错误码）
  ↓
前端按 02 文档对接
  ↓
发现问题 → 用 X-Request-ID 对账定位
  ↓
需要改契约 → 走 02 第 12 章变更流程（更新文档 → 通知双方 → 回归）
  ↓
联调清零，进入验收
```

### 6.2 Swagger 自测要求

后端提供联调的接口必须满足：

- 每个路由函数有中文 docstring（即 Swagger 上的接口描述）；
- 请求/响应模型用 Pydantic 定义并在 `Field(description=…)` 标注语义；
- Swagger 中可完成该接口的完整操作路径（含错误场景）。

### 6.3 请求追踪

- 客户端可携带 `X-Request-ID`；服务端自动生成 8 位 ID 并在响应头回传；
- 联调争议时，双方用同一 Request-ID 在后端日志中还原请求全貌。

### 6.4 常见联调问题速查

| 现象 | 原因 | 处理 |
|------|------|------|
| 跨域报错 | 前端来源不在 `CORS_ORIGINS` | 后端改 `.env` 白名单并重启 |
| 岗位详情 404 | 中文 `job_id` 未编码 | 前端 `encodeURIComponent` |
| 业务失败但 HTTP 200 | 以 `code===0` 判断 | 见 5.6 |
| 流式无打字机效果 | Nginx/代理缓冲 | Nginx `proxy_buffering off`（06 第 9.1 节） |
| AI 接口超时 | 同步调用 5-30s | 前端改用 SSE 流式接口 |
| 429 | 触发限流 | 开发环境关闭限流或调大阈值 |

## 7. 安全规范

### 7.1 现状与边界

当前系统**无用户认证**，接口可匿名调用（含按 `user_id` 读写任意用户数据）——**仅限内网开发与演示使用**，正式对外前必须落地 7.3 的规划项。

### 7.2 已落地的安全实践（必须保持）

| 项 | 实践 |
|----|------|
| 密钥管理 | API Key/数据库密码只进 `.env`（已 gitignore），禁止硬编码、禁止入库 |
| 注入防护 | 全部经 SQLAlchemy ORM 参数化查询，禁止字符串拼接 SQL |
| CORS | 白名单制（`CORS_ORIGINS`），不使用 `*` |
| 限流 | 生产环境按 IP 滑动窗口限流（默认 100 次/60s） |
| 错误信息 | 500 不向客户端泄露堆栈/内部信息 |
| 日志脱敏 | 日志禁止记录密码、Key、简历全文 |
| 依赖 | 依赖清单固定于 `requirements.txt`，新增依赖须团队确认 |

### 7.3 规划/待实现（上线前必须完成）

| 项 | 方案要点 | 相关文档 |
|----|---------|---------|
| 用户认证（JWT） | `users` 表加 `password_hash`（bcrypt 等单向哈希，**禁止明文**）；登录签发含用户ID+过期时间的 Token | 02 第 11 章 |
| 权限隔离 | 用户只能读写自己的数据（简历/经历/历史记录），接口层校验归属 | 01 第 14 章 |
| HTTPS | Nginx 终结 TLS（Let's Encrypt / 云证书） | 06 第 9 章 |
| 生产文档防护 | `/docs` 关闭或加访问控制 | 06 第 6 章 |
| 文件上传安全 | 简历上传功能须校验格式/大小/类型白名单 | 01 第 14 章 |

### 7.4 数据安全

学生数据（学习经历、技能自评、简历内容、AI 分析结论）属个人敏感信息：

- 采集遵循最小必要原则（当前字段即业务所需）；
- 上线前落实权限隔离；数据库备份文件同密级管理；
- 对外演示/截图时使用脱敏数据。

## 9. Git 协作规范

### 9.1 分支策略

| 分支 | 用途 | 状态 |
|------|------|------|
| `main` | 随时可运行的可交付版本 | 当前唯一分支（单分支开发） |
| `develop` | 集成验证 | `规划/待实现`（团队扩大后启用） |
| `feature/<功能>` | 功能开发，如 `feature/job-favorite`、`feature/ai-profile` | `规划/待实现` |

当前单分支约束：`main` 保持可运行，改动前先确认回归测试通过再提交；无法保证时先本地验证完再 push。

### 9.2 Commit 规范

格式：`<类型>: <描述>`（中文/英文均可，描述说清"改了什么、为什么"）。

| 类型 | 用途 | 示例 |
|------|------|------|
| feat | 新功能 | `feat: 新增岗位收藏接口` |
| fix | 缺陷修复 | `fix: 修复岗位匹配空技能列表崩溃` |
| docs | 文档 | `docs: 同步02文档新增收藏接口契约` |
| style | 格式 | `style: 统一user_service缩进` |
| refactor | 重构（不改行为） | `refactor: 抽取_commit_and_refresh公共方法` |
| perf | 性能 | `perf: 岗位列表查询加预加载` |
| test | 测试 | `test: 补充收藏接口404用例` |
| chore | 杂务 | `chore: 更新requirements版本` |

### 9.3 合并与变更纪律

1. 合并到 `main` 前自查：受影响文档已同步（01 第 1 章一致性规则）；
2. 回归命令（[01 第 12.3 节](./01-项目开发说明书.md)）通过后再合并；
3. 接口契约/表结构变更 → 次版本号 +1，commit message 与 02/03 变更说明呼应；
4. `.env`、`*.db`、`node_modules/`、`__pycache__/` 等不应入库（`.env`、`node_modules/`、`__pycache__/` 已被 `.gitignore` 覆盖；**`*.db` 尚未覆盖，且 `backend/ai_job_analysis.db` 当前已被 Git 追踪**——属待单独处理的仓库卫生问题，需经维护者确认后再添加忽略规则并解除追踪，本次不擅自改动）。

## 10. 性能验收标准

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 普通接口响应（非 AI） | P95 < 500ms | Swagger/脚本计时 |
| AI 同步接口 | < 10s（Mock 模式应 < 1s） | `test_api.py` 计时 |
| SSE 首字节 | < 2s（打字机启动） | 前端 DevTools Network |
| 并发能力 | 50+ 用户同时访问不降级 | 压测（`规划/待实现` locust） |
| 数据库 | 单表查询走索引（`user_id`） | `DB_ECHO=true` 抽查 SQL |

已知瓶颈与对策（详见 [01 第 13 章](./01-项目开发说明书.md)）：

- 同步 AI 调用阻塞 worker（5-30s）→ 前端优先 SSE；远期异步任务化；
- 限流/Token 统计为进程内存 → 多 worker 部署失效，规划 Redis。

## 11. AI 辅助开发协作守则

在 [01 第 15 章](./01-项目开发说明书.md)五条原则下的操作细则：

### 11.1 向 AI 提需求时必须提供

- 项目背景（一段话：本项目是什么、当前状态）；
- 相关契约（02 文档对应章节 / 表结构）；
- 目标模块的现有代码（保持风格一致）；
- 明确的改动范围（"只新增 xx，不改 yy"）。

### 11.2 AI 生成代码的验收清单

- [ ] 分层合规：业务在 Service，API 层无逻辑；
- [ ] 响应走 `success()/error()`，异常用自定义异常类；
- [ ] 未修改既有接口签名与数据库字段（ diffs 检查）；
- [ ] 文件头中文注释、无 TODO 残留在主流程；
- [ ] 附带测试用例且本地运行通过。

### 11.3 禁止行为（AI 生成即拒绝合入）

- × 自动修改数据库结构 / 删除已有接口；
- × 重构核心架构（分层、单例、统一响应）；
- × 引入未经确认的第三方依赖；
- × 生成"假装已实现"的注释或文档描述。
