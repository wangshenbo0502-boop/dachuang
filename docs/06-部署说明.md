## 2. 环境变量（`backend/.env`）

复制 `.env.example` 为 `.env` 后修改。所有变量由 `backend/app/config.py` 读取，**修改后需重启服务**。

### 2.1 应用

| 变量 | 默认 | 说明 |
|------|------|------|
| `APP_ENV` | development | development / production / testing（影响连接池、限流默认值、日志级别） |
| `APP_DEBUG` | true（dev） | FastAPI debug 开关 |
| `APP_NAME` | AI就业竞争力分析助手 | 服务名 |
| `APP_VERSION` | 1.2.0 | 接口版本标识（`GET /` 返回） |

### 2.2 数据库

| 变量 | 默认 | 说明 |
|------|------|------|
| `DATABASE_URL` | `sqlite:///./ai_job_analysis.db` | SQLite 或 MySQL：`mysql+pymysql://user:password@127.0.0.1:3306/ai_job_analysis?charset=utf8mb4` |
| `DB_POOL_SIZE` | dev=5 / prod=20 | MySQL 连接池（SQLite 忽略） |
| `DB_POOL_RECYCLE` | 3600 | 连接回收秒数 |
| `DB_ECHO` | false | 打印 SQL 日志（调试用） |

### 2.3 CORS

| 变量 | 默认 | 说明 |
|------|------|------|
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 逗号分隔的前端来源白名单 |

### 2.4 DeepSeek AI（详见 [04 第 3 章](./04-AI模块设计文档.md)）

| 变量 | 默认 | 说明 |
|------|------|------|
| `DEEPSEEK_API_KEY` | 空 | **空/占位值 = Mock 模式**；获取：https://platform.deepseek.com/ |
| `DEEPSEEK_BASE_URL` | https://api.deepseek.com | OpenAI 兼容端点 |
| `DEEPSEEK_MODEL` | deepseek-chat | 模型名 |
| `AI_TIMEOUT` | 60 | 单次请求超时（秒） |
| `AI_MAX_RETRIES` | 3 | 最大重试 |
| `AI_TEMPERATURE` / `AI_MAX_TOKENS` | 0.7 / 4000 | 生成参数默认值 |
| `AI_COST_BUDGET_PER_DAY` | 10.0 | 每日成本预算（美元，估算） |
| `AI_COST_WARNING_THRESHOLD` | 0.8 | 告警阈值 |

### 2.5 限流与日志

| 变量 | 默认 | 说明 |
|------|------|------|
| `RATE_LIMIT_ENABLED` | dev=false / prod=true | 按 IP 滑动窗口限流 |
| `RATE_LIMIT_REQUESTS` / `RATE_LIMIT_WINDOW` | 100 / 60 | 窗口内最大请求数 / 窗口秒数 |
| `LOG_LEVEL` | dev=DEBUG / prod=INFO | 日志级别 |
| `LOG_FORMAT` | 带时间戳格式 | 日志格式 |

> `.env` 已被 `.gitignore` 排除，**严禁提交真实 Key/密码**；`env.example` 保持占位值。

## 3. 后端部署

### 3.1 安装依赖

```bash
cd backend
python -m venv venv
source venv/Scripts/activate        # Windows Git Bash；Windows PowerShell 用 venv\Scripts\Activate.ps1
pip install -r requirements.txt
# 国内镜像：
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
```

### 3.2 初始化数据库

```bash
python init_db.py
# 未配置 DATABASE_URL 时自动使用 SQLite：backend/ai_job_analysis.db
# 期望输出 9 张表（清单见 [03 第 7 章](./03-数据库设计文档.md)）
```

### 3.3 启动服务（正确命令）

```bash
# 开发（自动重载）
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
# 生产（多 worker）
uvicorn main:app --host 0.0.0.0 --port 8000 --workers 4
```

启动后验证：

| 检查点 | 地址 | 期望 |
|--------|------|------|
| 服务信息 | http://localhost:8000/ | `code=0`，version=1.2.0 |
| 健康检查 | http://localhost:8000/api/health | `status=healthy`，`ai_mode=mock`（未配 Key）或 `live` |
| Swagger | http://localhost:8000/docs | 可见全部接口并可调试 |

## 5. AI 配置（Mock → Live 切换）

1. 编辑 `backend/.env`：`DEEPSEEK_API_KEY=sk-xxxx`。
2. 重启服务：`uvicorn main:app --reload`。
3. 验证：`GET /api/health` → `"ai_mode": "live"`；此后 AI 接口返回真实结果（`is_mock=false`）。
4. 成本监控：`GET /api/usage` 查看 Token 用量与预算标记；预算/告警仅展示，不自动熔断（[04 第 6 章](./04-AI模块设计文档.md)）。
5. 保持 Mock 联调：删掉 Key 即回到 Mock 模式，前端无感知。

## 6. 数据库切换（SQLite → MySQL）

1. 创建库：`CREATE DATABASE ai_job_analysis DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
2. 修改 `DATABASE_URL`（见 2.2），注释 SQLite 行。
3. `python init_db.py` 重新建表（结构变更历史不会迁移，数据需另行导入）。
4. 验证 9 张表齐全、健康检查正常。

注意事项：SQLite 下外键级联由 ORM 层保证、MySQL 由 FK 保证（[03 第 1.2 节](./03-数据库设计文档.md)）；无 Alembic 迁移工具（`规划/待实现`）。

全部通过即达到 [01 第 12.3 节](./01-项目开发说明书.md) 验收基线。

### 7.1 性能验收基线（部署后建议抽查）

| 指标 | 目标 | 部署相关注意 |
|------|------|-------------|
| 普通接口（非 AI） | P95 < 500ms | 数据库连接池按环境配置（`DB_POOL_SIZE`） |
| AI 同步接口 | < 10s | Nginx `proxy_read_timeout` ≥ 120s（9.1 节）；Mock 模式应 < 1s |
| SSE 首字节 | < 2s | Nginx `proxy_buffering off` 必须开启，否则无打字机效果 |
| 并发 | 50+ 用户 | 多 worker 时内存限流/Token 统计各自独立（见 9.2 节） |

完整指标与测量方式见 [开发文档 第 10 章](./开发文档.md)；压测工具为 `规划/待实现`（locust 等，见 9.3 节）。

## 8. 已知部署相关问题

| 问题 | 现象 | 处置 |
|------|------|------|
| `python main.py` 不启动服务 | 命令执行后直接退出 | **用 `uvicorn main:app`**；`规划/待实现`：在 main.py 补 `if __name__ == "__main__": uvicorn.run(...)` |
| 中文 job_id 请求 404/乱码 | URL 未编码 | `encodeURIComponent("Java后端开发工程师")` |
| SSE 被缓冲 | 流式无打字机效果 | Nginx 需 `proxy_buffering off`（响应头已带 `X-Accel-Buffering: no`） |
| 429 限流 | 压测/频繁刷新触发 | 生产按需调大 `RATE_LIMIT_REQUESTS` |
| Token 统计清零 | 服务重启后 `/api/usage` 归零 | 进程内存实现，属预期（[04 第 6 章](./04-AI模块设计文档.md)） |

## 9. 生产部署规划（`规划/待实现`，无现成配置）

以下为推荐目标架构，**当前仓库尚无对应配置文件**，实施时先补充并回归本文档：

```
用户浏览器
   │ HTTPS
   ▼
Nginx（规划）
   ├── /            → 前端静态文件（frontend/dist）
   └── /api         → 反向代理 uvicorn（多 worker）
                        ├── MySQL 8（utf8mb4）
                        ├── DeepSeek API（live 模式）
                        └── knowledge/（本地文件，随代码部署）
```

### 9.1 建议的 Nginx 参考片段（示例，需自建 `/etc/nginx/...`）

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    location / {
        root /opt/ai-job/frontend/dist;
        try_files $uri $uri/ /index.html;        # Vue history 路由
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_buffering off;                      # SSE 必需
        proxy_read_timeout 120s;                  # AI 同步调用耗时上限
    }
}
```

### 9.2 进程管理

- systemd 单元或 supervisor 拉起 `uvicorn main:app --workers 4`（示例，未提供现成文件）。
- 注意：多 worker 下**内存限流与 Token 统计各自独立**，准确限流需 Redis（`规划/待实现`）。
