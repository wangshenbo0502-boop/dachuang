# 管理员独立系统：分阶段提示词与验收

> 供后续获得开发授权的 AI 使用。当前交付仅为 Markdown 文档。执行时由主智能体按阶段顺序完成；用户未明确授权时不得使用子智能体。

**目标：**完成与求职/招聘系统分离的管理员前后端，提供真实的账号管理、岗位治理、业务只读查询和审计。

**架构：**独立 `admin-frontend/`、`admin-backend/`、管理数据库；原业务后端通过受保护的 `/internal/admin/v1` 暴露管理能力。业务后端不调用管理后端，管理后端不连接原业务库。

**技术栈：**Vue 3、TypeScript、Vite、Pinia、Element Plus；FastAPI、SQLAlchemy 2、Pydantic 2、HTTPX、Argon2、PyJWT；新管理库独立 Alembic。

先阅读 [总提示词](README.md)、[架构与接口契约](01-架构与接口契约.md)、[核心关键代码](02-核心关键代码.md)。每个阶段提示词默认包含总提示词中的全部约束。

## 1. 执行约定

1. 顺序为 P0 → P1 → P2 → P3 → P4 → P5 → P6；每阶段有独立结果。P4 的静态页面可以在服务契约确定后开始，但真实验收必须等待后端。
2. 一次只给 AI 当前阶段和它需要的上下文，降低遗漏。不要一次生成整套代码后才检查权限边界。
3. 代码片段提供关键实现；AI 必须完成真实应用装配，不能返回只有目录、注释、空函数或固定数据的半成品。
4. 阶段复盘写 `docs/管理员独立系统/实施记录.md`，只记录实际工作和证据；本次不会预先创建虚假的实施记录。
5. 用户只授权部分阶段时，在完成该阶段后停止。未授权的提交、推送、上线不能夹带执行。
6. 所有下述测试名、命令和预期结果都是**未来验收要求**，不表示本次已运行或已经通过。

### 通用阶段输出格式

```text
阶段：P{实际阶段编号}
状态：PASS / PARTIAL / BLOCKED / NOT TESTED
完成行为：写清用户能做什么，以及权限/失败时会发生什么。
文件：列出实际创建/修改的路径。
契约变化：列出请求、响应、数据库迁移和兼容性变化；没有则写无。
验证：命令、退出码、用例结果、必要证据路径。
未完成/风险：只写真实未完成项，不把没有运行的验证写成通过。
下一阶段输入：确定的模块接口、文件和阻塞依赖。
```

## 9. 测试矩阵与完成门槛

| 编号 | 验证场景 | 通过标准 |

## 11. 配置与启动契约

所有 `.env.example` 只能包含说明、空秘密项和本机示例。真实值在运行环境注入，不写文档、截图或日志。管理配置不得调用无明确路径的 load_dotenv 搜索父目录。

| 应用 | 环境变量 | 规则 |
|---|---|---|
| 管理后端 | `ADMIN_ENV` | development/testing/production |
| 管理后端 | `ADMIN_DATABASE_URL` | 独立管理库；production 用 PostgreSQL |
| 管理后端 | `ADMIN_ORIGIN` | development 示例 `http://127.0.0.1:5174`；production 是实际管理 HTTPS origin |
| 管理后端 | `BUSINESS_INTERNAL_BASE_URL` | development 示例 `http://127.0.0.1:8000`；只能由服务端配置 |
| 两个后端 | `INTERNAL_ADMIN_SERVICE_SECRET` | 独立随机密钥，至少 32 字节熵，不同于业务 JWT_SECRET |
| 业务后端 | `INTERNAL_ADMIN_ENABLED` | 默认 false，按环境显式开启 |
| 管理前端 | 无秘密变量 | API 使用同源 `/admin-api/v1`；服务密钥不允许以 VITE_ 开头 |

管理会话 Cookie 的名字和 Secure 属性由 ADMIN_ENV 决定，不暴露可让 production 关闭安全属性的随意开关。session 有效期首期固定 8 小时；若改为配置须在契约和测试中同步。

实施完成后的本地启动顺序：

1. 为业务和管理进程分别注入配置，不共用一个 Shell 中的泛用 `DATABASE_URL` 覆盖两套程序。
2. 对管理库执行迁移，通过 `python -m admin_app.cli.create_admin` 创建首个管理员。
3. 在 `backend/` 启动 `python -m uvicorn main:app --host 127.0.0.1 --port 8000`。
4. 在 `admin-backend/` 启动 `python -m uvicorn admin_app.main:app --host 127.0.0.1 --port 8001`。
5. 在 `frontend/` 运行 `npm.cmd run dev`，在 `admin-frontend/` 运行 `npm.cmd run dev`。
6. 用两个独立应用完成会话及管理行为验证；本地地址不是上线地址。

业务默认库若使用相对 SQLite 路径，必须从正确工作目录启动或明确使用绝对数据库路径，避免悄悄新建空业务库。测试数据库使用随机临时路径，拒绝回落到真实业务默认文件。

## 12. 部署与回滚提示

管理前端生产站点单独域名或独立 origin；`/admin-api/v1` 同源反向代理到管理后端。管理 API 不反向代理到原业务进程。管理站点与业务站点的公网代理均拒绝 `/internal/`；内部调用直接走受控服务网络。

以下仅是 Nginx server 内的路径片段，upstream 名字为待配置服务名；需要部署者补齐实际 HTTPS server、证书和 upstream，不是可直接宣称生产可用的完整配置：

```nginx
location ^~ /internal/ {
    return 404;
}

location ^~ /admin-api/ {
    proxy_pass http://admin_backend;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 20s;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

内部路由可以注册到原业务 app，但不出现在面向用户的公开 OpenAPI；P3 独立导出内部 router 的 schema，或提供仅受控网络可读的内部契约产物。仅隐藏 Swagger 不是安全措施，仍必须有网络限制和服务验签。

发布顺序：备份并验证恢复方案 → 原业务兼容性迁移/治理代码 → 配置受保护内部接口 → 管理库迁移 → 管理后端 → 管理前端 → 验证。两套数据库的备份和凭证必须分开管理。

回滚顺序：停止新的管理写请求 → 保留并核对 pending/unknown → 回滚管理前后端版本或关闭内部 API → 保留已提交业务治理状态及新增兼容列/凭据。禁用的账号和受限制岗位不能随程序回滚自动解禁。

**不能回滚到不认识 moderation_status 的旧业务版本后仍声称平台限制有效。** 如需回滚业务治理代码，先明确处理仍被限制的对象并制定维持限制的兼容版本；不得通过删除列/凭据绕过此问题。
