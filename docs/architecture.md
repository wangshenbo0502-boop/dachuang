## 1. 项目概述

### 1.1 项目背景

当前大学生就业形势严峻，计算机专业学生往往难以准确评估自身竞争力，也不知道该如何针对性地提升。本项目旨在通过 AI 技术，帮助计算机专业大学生：

- 清晰认知自身技术能力水平
- 了解目标岗位的技能要求
- 获取简历优化建议
- 制定个性化的成长路线

### 1.2 项目定位

**面向群体**：计算机专业在校大学生（本科/硕士）

**核心价值**：
- 客观的技术能力评估
- 数据驱动的岗位匹配
- 专业的简历优化建议
- 可执行的成长规划

### 1.3 核心功能

| 模块 | 子功能 | 优先级 |
|------|--------|-------|
| 用户管理 | 注册、登录、个人信息、学习经历、项目经历、技能管理 | P0 |
| AI就业画像 | 技术能力雷达图、综合评分、优劣势分析、就业画像报告 | P0 |
| 岗位匹配 | 岗位列表、岗位详情、智能匹配、匹配度评分 | P1 |
| 简历优化 | 简历上传解析、AI优化建议、多模板预览、PDF导出 | P1 |
| 成长规划 | 个性化学习路线、阶段目标、进度跟踪、资源推荐 | P2 |

## 2. 技术选型

### 2.1 前端技术栈

| 技术 | 选型理由 |
|------|---------|
| **Vue 3** | 组合式 API 灵活高效，学习曲线平缓，团队上手快 |
| **Vite** | 极速的冷启动和热更新，开发体验好 |
| **TypeScript** | 类型安全，减少运行时错误，提升代码可维护性 |
| **Vue Router 4** | 官方路由，与 Vue 3 完美配合 |
| **Pinia** | Vue 官方推荐的状态管理，TypeScript 支持好 |
| **Axios** | 成熟的 HTTP 客户端，拦截器功能完善 |

### 2.2 后端技术栈

| 技术 | 选型理由 |
|------|---------|
| **FastAPI** | 高性能异步框架，自动生成 API 文档，Python 生态适合 AI |
| **SQLAlchemy 2.0** | 成熟的 Python ORM，支持异步，类型提示完善 |
| **Pydantic v2** | 数据校验与序列化，与 FastAPI 无缝集成 |
| **PyMySQL** | MySQL 数据库驱动 |

### 2.3 AI 与数据

| 技术 | 选型理由 |
|------|---------|
| **DeepSeek API** | 开源可替代，中文能力强，成本低，推理速度快 |
| **JSON 知识库** | 初期轻量方案，后续可平滑迁移到向量数据库 + RAG |

### 2.4 为什么不选 X？

- **为什么不用 Django？** — FastAPI 更轻量，异步性能更好，更适合 AI 接口场景
- **为什么不用 PostgreSQL？** — MySQL 团队更熟悉，初期功能需求完全够用
- **为什么不用 Next.js？** — 团队 Vue 经验更丰富，后续可根据需要迁移

### 3.2 后端分层架构

后端采用经典的**分层架构**，每层职责单一：

```
┌─────────────────────────────────────────────┐
│  API Layer (app/api/)                        │
│  - 接收 HTTP 请求                             │
│  - 参数校验（调用 Pydantic Schema）            │
│  - 调用 Service 层处理业务                     │
│  - 返回统一格式的响应                          │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  Service Layer (app/services/)               │
│  - 核心业务逻辑                               │
│  - 协调多个 Model 和外部服务（AI/知识库）       │
│  - 事务控制                                   │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  Model Layer (app/models/)                   │
│  - SQLAlchemy ORM 模型                        │
│  - 数据库 CRUD 操作                           │
│  - 数据关系定义                               │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  Database Layer (app/database/)              │
│  - 数据库连接配置                             │
│  - 会话管理（Session）                        │
└─────────────────────────────────────────────┘
```

## 6. 接口设计原则

### 6.1 RESTful 规范

- 使用 HTTP 方法语义：GET（查询）、POST（创建）、PUT（更新）、DELETE（删除）
- 路径使用名词复数，如 `/api/users`、`/api/reports`
- 版本控制通过 URL 前缀，如 `/api/v1/...`（初期可省略）

### 6.2 统一响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- `code`：0 表示成功，非 0 表示错误
- `message`：描述信息
- `data`：业务数据

### 6.3 错误码设计

| 错误码 | 说明 |
|--------|------|
| 0 | 成功 |
| 1 | 通用错误 |
| 1001 | 参数校验失败 |
| 1002 | 用户不存在 |
| 1003 | 密码错误 |
| 1004 | Token 无效/过期 |
| 2001 | AI 服务调用失败 |
| 2002 | 知识库加载失败 |
| 3001 | 资源不存在 |

## 8. 可扩展性设计

### 8.1 前端迁移策略（Vue → React + Next.js）

当前目录设计已考虑未来可能的迁移：

1. **API 层独立**：`src/api/` 不依赖框架，可直接复用
2. **状态管理解耦**：Pinia Store 逻辑可迁移到 Zustand/Redux
3. **组件化设计**：每个 .vue 文件的 template/script/style 可分别迁移
4. **路由独立**：路由配置与页面组件分离

### 8.2 知识库升级策略（JSON → RAG）

1. 初期使用 JSON 静态数据，通过 `KnowledgeService` 封装访问
2. 升级时替换 `KnowledgeService` 内部实现，接入向量数据库
3. 上层业务代码（Service 层）无需修改

### 8.3 AI 模型切换

- DeepSeek 客户端通过 `DeepSeekClient` 类封装
- 未来切换模型时，新增一个 Client 类实现相同接口即可
- Service 层不直接依赖具体模型

## 9. 安全设计（规划）

- **认证**：JWT Token 认证，Token 存储在 HTTP-only Cookie
- **授权**：基于角色的权限控制（初期仅普通用户，后续加管理员）
- **输入校验**：所有入参通过 Pydantic Schema 校验
- **SQL 注入防护**：使用 ORM 参数化查询
- **敏感信息**：密码加密存储（bcrypt），API Key 通过环境变量管理
- **CORS**：后端配置 CORS 策略，生产环境限制来源域名
