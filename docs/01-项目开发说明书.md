## 2. 项目概述

### 2.1 定位

面向计算机专业大学生的 AI 就业竞争力分析平台。学生录入个人经历后，系统结合本地岗位知识库与 DeepSeek 大模型，自动生成就业画像、岗位匹配、简历优化与成长规划建议。

### 2.2 核心业务闭环

```
学生填写经历（用户管理）
      ↓
AI 就业画像分析  ←── 知识库检索（岗位/技能要求）
      ↓
AI 岗位匹配（关键词粗排 + AI 精排）
      ↓
AI 简历优化
      ↓
AI 成长规划
```

四个 AI 功能均支持两种输入方式：`user_id`（读取已保存资料）或直接内联用户信息；同步接口落库保存历史，流式接口（SSE）提供打字机效果但不落库。

## 4. 系统架构

```
浏览器 (Vue3 SPA, :5173)
    │  HTTP /api  (CORS: localhost:5173)
    ▼
FastAPI (:8000)
 ├──中间件: 请求日志 + Request-ID + 滑动窗口限流
 ├──全局异常处理器 (AppException / ValidationError / Exception)
 ├──API 层 app/api/*  ──► Service 层 app/services/*
 │                            ├──► Models app/models/* ──► SQLite / MySQL
 │                            ├──► AI层 app/ai/* ──► DeepSeek API (或 Mock)
 │                            └──► KnowledgeService app/knowledge/*
 │                                     └──► knowledge/ (Markdown + KeywordIndex)
 └──流式: app/api/streaming.py ──► SSE (text/event-stream)
```

要点：

1. **分层**：`API → Service → Model/Knowledge/AI`，禁止跨层（详见第 9 章）。
2. **知识库双层结构**：`knowledge/` 是独立于后端的通用 RAG 模块；`backend/app/knowledge/` 是适配层，后端业务只能通过 `KnowledgeService` 单例访问知识，不得自行读文件。
3. **AI 双模式**：`DEEPSEEK_API_KEY` 未配置时全链路自动降级为 Mock（响应带 `is_mock: true`），保证无 Key 也能开发联调。
4. **岗位数据不落库**：岗位（jobs）来自知识库 Markdown 文档而非数据库表；数据库只保存**匹配记录快照**。

## 7. 全局开发约定（强制）

以下约定适用于全部后端接口与文档，`02/03/04/05/06` 不再重复定义，引用本章。

### 7.1 接口基础

| 项 | 约定 |
|----|------|
| 接口前缀 | **`/api`（当前实现）**。`/api/v1` 版本化前缀为 `规划/待实现`，实施前不得擅自变更前缀 |
| 数据格式 | 请求/响应 `Content-Type: application/json`（SSE 除外） |
| 方法语义 | GET 查询、POST 创建/触发、PUT 整组替换；未使用 DELETE |
| ID 类型 | 业务记录主键为自增整数；`job_id` 为字符串（知识文档文件名，如 `Java后端开发工程师`） |
| 时间 | `YYYY-MM-DD HH:MM:SS`（ISO-8601），由数据库 `func.now()`生成 |
| 分页 | 查询参数 `page`(默认1) / `page_size`(默认20，≤50)；响应 `items/total/page/page_size`（`PaginatedData`模型） |
| 认证 | **未实现**。规划 JWT Bearer；当前所有接口无需认证 |

### 7.2 统一响应结构

成功与失败均为三段式（实现于 `app/utils/response.py`）：

```json
// 成功：code = 0（注意：不是 200）
{ "code": 0, "message": "success", "data": { } }

// 失败：code = 业务错误码，data 可携带详情
{ "code": 1001, "message": "参数校验失败", "data": [...] }
```

### 7.3 统一错误码（`ErrorCode` 枚举）

| code | 名称 | HTTP 状态 | 场景 |
|------|------|-----------|------|
| 0 | SUCCESS | 200/201 | 成功 |
| 1 | INTERNAL_ERROR | 500 | 未捕获异常/服务器内部错误 |
| 1001 | PARAM_VALIDATION_ERROR | 422 | Pydantic 参数校验失败（data 携带错误明细） |
| 2001 | NOT_FOUND | 404 | 资源不存在（**规范值**，见下方已知偏差） |
| 2002 | ALREADY_EXISTS | 409 | 资源已存在（已定义，暂无使用方） |
| 3001 | AI_SERVICE_ERROR | 500 | AI 服务调用失败 |
| 3002 | AI_API_ERROR | 500 | AI API 返回错误 |
| 3003 | AI_RETRY_EXHAUSTED | 500 | AI 重试耗尽 |
| 3004 | AI_PARSE_ERROR | 500 | AI 返回 JSON 解析失败 |
| 4001 | UNAUTHORIZED | 401 | 认证失败（规划，未启用） |
| 4002 | FORBIDDEN | 403 | 权限不足（规划，未启用） |
| 429 | —（限流） | 429 | 触发滑动窗口限流 |

**已知偏差（待修复，先如实记录）**：

1. `ResourceNotFoundError` 当前实际返回 `code=3001`（构造于 `app/utils/exceptions.py`），与规范值 2001 冲突，且与 `AI_SERVICE_ERROR=3001` 撞号。修复时同步 `02` 文档。
2. AI 层 `AIServiceError` 不是 `AppException` 子类，冒泡后由兜底处理器转为 `HTTP 500 / code=1`，而非 3001-3004。业务层当前未捕获 AI 异常。
3. 限流响应的 body `code=429`，不属于 `ErrorCode` 枚举。

## 9. 分层架构与开发边界（强制）

### 9.1 调用规则

```
API 层（app/api/）     只做：参数接收(Pydantic)、调用 Service、组装统一响应。禁止写业务逻辑。
Service 层（app/services/） 业务逻辑、事务控制、编排 AI/知识库/Model。可互相调用，禁止反向调用 API。
Model 层（app/models/）    只做 ORM 定义；CRUD 逻辑写在 Service。
```

- 新增路由必须在 `main.py` 注册：`app.include_router(xxx.router)`。
- 新增模块需同步创建 `api/xxx.py` + `services/xxx_service.py` + `schemas/xxx.py`（如需）+ `models/xxx.py`（如需）。
- 数据库会话一律通过依赖注入 `Depends(get_db)`，业务异常回滚由 Service 自己 `rollback()`（参考 `user_service._commit_and_refresh`）。

### 9.2 AI 模块边界（来自 `docs/specs` 交接契约，持续有效）

1. AI 业务代码**禁止直接查询** `User/UserSkill/UserProject` 等 ORM 模型获取用户数据；统一使用：
   - 进程内：`UserService(db).get_user_context(user_id)` → `StudentContextResponse`；
   - HTTP：`GET /api/users/{user_id}/context`。
2. 所有 DeepSeek 调用必须经 `app/ai/deepseek_client.py` 的 `DeepSeekClient.instance()`，禁止在业务层直接 new OpenAI 客户端。
3. System Prompt 统一放 `knowledge/prompts/*.md` 外置文件，通过 `SystemPrompts.get(name, fallback)` 加载；修改 Prompt 不需要改代码、不需要重启。
4. AI 返回 JSON 必须使用 `chat_json()`（自带双层容错），不得自行 `json.loads` 裸解析。
5. 知识检索必须经 `KnowledgeService.instance()`，禁止绕过索引直接读 `knowledge/documents/`。

### 9.3 其他边界

- 环境变量/密钥只进 `.env`；`.env` 不入库，`env.example` 保持同步。
- 统一响应只能用 `utils/response.py` 的 `success()/error()`，禁止自定义返回结构。
- 异常只能抛 `utils/exceptions.py` 中的自定义异常（AI 层为 `AIServiceError`），禁止裸 `raise Exception`；API 层不捕获异常，交给全局处理器。

## 10. 异常处理规范

全局处理器（`main.py`）按以下优先级兜底：

| 异常 | 处理结果 |
|------|---------|
| `AppException`（含 `ResourceNotFoundError`、`DatabaseConfigurationError`） | 按异常自带的 `status_code` + `code` 返回三段式 |
| `RequestValidationError` | HTTP 422，`code=1001`，data=错误明细数组 |
| 其他一切异常 | HTTP 500，`code=1`，打印堆栈，不向客户端泄露内部信息 |

约定：

1. Service 层发现业务错误 → 抛自定义异常；数据库操作失败 → `rollback()` 后重新抛出。
2. 前端判成功的唯一标准是 `code === 0`；HTTP 状态码仅用于网络层判断。
3. AI 增强逻辑（如岗位匹配精排）失败时允许**静默降级**（保留粗排结果），这是唯一允许吞异常的场景。

### 12.2 验收规则（Definition of Done）

一个功能要标记为"已实现"，必须同时满足：

1. **代码**：分层合规（第 9 章），文件头注释完整，无 TODO 残留于主流程。
2. **契约**：接口/表结构与 `02/03` 文档一致；响应符合统一结构（7.2）。
3. **测试**：11.2 的测试要求全部满足且通过；`python test_job_match.py` 与 `python -m unittest tests.test_user_api` 回归通过。
4. **文档**：受影响的文档已同步，规划项未冒充为已实现。
5. **可演示**：`uvicorn main:app` 启动后，通过 `/docs` Swagger 可完成该功能的完整操作路径。
6. **性能**：满足性能验收基线——普通接口 P95 < 500ms、AI 同步接口 < 10s、SSE 首字节 < 2s、并发 50+ 用户不降级（完整指标与测量方式见 [开发文档 第 10 章](./开发文档.md)）。
7. **安全**：不引入新的硬编码密钥；日志未新增敏感信息输出（安全规范见 [开发文档 第 7 章](./开发文档.md)）。

| 限流/Token 统计为进程内存实现 | 多进程部署失效 | 低 | 规划 Redis（见 04/06） |
| 无认证体系 | 仅限内网/演示使用 | 低（当前阶段） | 规划 JWT（见 02 第 9 章） |

## 15. AI Agent 协作守则（给 AI 辅助编码）

1. **先读后写**：动手前先读本文档 + 对应领域文档 + 目标模块现有代码，保持既有风格（Mapped 写法、单例模式、三段式响应）。

4. **契约先行**：改接口先改 `02`，改表先改 `03`，再动代码。
5. **验证闭环**：改完运行第 12.3 节命令自测，报告真实结果。
