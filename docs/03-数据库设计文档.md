## 1. 概述

| 项 | 约定 |
|----|------|
| 数据库 | **开发默认 SQLite**（`backend/ai_job_analysis.db` 文件库）；**生产 MySQL 8**（`utf8mb4`），通过 `DATABASE_URL` 切换 |
| ORM | SQLAlchemy 2.0（`DeclarativeBase` + `Mapped/mapped_column`），同步 Session |
| 连接管理 | `app/database/connection.py`（Engine 单例，`pool_pre_ping`）；`app/database/session.py`（`get_db` 依赖注入，请求级会话） |
| 迁移工具 | **无（`规划/待实现` Alembic）**。改表 = 修改模型 + 重建库（见第 8 章） |
| 建表 | `python backend/init_db.py`（`Base.metadata.create_all`，只建缺失表，不改已有表） |

### 1.1 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 表名 | 复数 snake_case | `users`、`job_match_records` |
| 主键 | `id`，自增整数 | — |
| 外键 | `<实体>_id` | `user_id` |
| 时间 | `created_at` / `updated_at`，`DateTime(timezone=True)` + `server_default=func.now()` | — |
| JSON 字段 | SQLAlchemy `JSON` 类型（SQLite 存 TEXT，MySQL 存 JSON） | `tech_stack`、`raw_result` |

### 1.2 ER 关系总览

```
users (1)
 ├──∞ user_skills          (CASCADE)   学生自评技能
 ├──∞ user_projects        (CASCADE)   项目经历
 ├──∞ user_competitions    (CASCADE)   竞赛经历
 ├──∞ user_internships     (CASCADE)   实习经历
 ├──∞ job_match_records    (SET NULL)  岗位匹配历史（快照）
 ├──∞ profile_analyses     (SET NULL)  就业画像历史（快照）
 ├──∞ resume_optimizations (SET NULL)  简历优化历史（快照）
 └──∞ growth_plans         (SET NULL)  成长规划历史（快照）
```

两类从表、两种删除策略：

1. **经历类**（skills/projects/competitions/internships）：`ForeignKey("users.id", ondelete="CASCADE")` + ORM `relationship(cascade="all, delete-orphan")`。用户删除则经历删除；业务上经历通过"整组替换"更新。
2. **记录快照类**（匹配/画像/简历/规划）：`ondelete="SET NULL"`，`user_id` 可空。用户删除后记录保留（匿名快照），保证历史可查。

> **SQLite 注意**：连接层未开启 `PRAGMA foreign_keys=ON`，SQLite 下数据库级外键不强制；级联删除实际由 ORM 层 `relationship cascade` 保证。MySQL 下由 FK `ondelete` 直接保证。切换数据库时行为一致，但不要绕过 ORM 直接写 SQL 删除用户。

### 1.3 数据库设计原则

数据库只负责三件事：**数据持久化 + 关系维护 + 查询支持**。

| 原则 | 说明 |
|------|------|
| 业务逻辑不入库 | 计算、编排、AI 调用一律在 Service 层；禁止存储过程/触发器承载业务 |
| Prompt 不入库 | System Prompt 统一外置在 `knowledge/prompts/*.md`（见 [04 第 7 章](./04-AI模块设计文档.md)），数据库不存 Prompt 模板 |
| 不存临时数据 | AI 调用的中间计算过程不落库；只存**最终结果快照**（`raw_result` 保存的是 AI 原始返回，用于审计回放，属结果而非过程，为唯一例外） |
| 查询走 ORM | 全部经 SQLAlchemy 参数化查询，禁止拼接 SQL 字符串（防注入，见 [开发文档 第 7 章](./开发文档.md)） |
| 岗位数据不入库 | 岗位来源于知识库 Markdown（见 [05 第 1 章](./05-RAG知识库设计文档.md)）；库中仅存匹配记录**快照** |

## 5. 数据流与生命周期

```
写入路径：
  用户管理接口 ──► users + 4 张经历表（整组替换 = 先删后插，单事务）
  POST /api/match ──► job_match_records（有匹配结果才写）
  POST /api/analysis | /api/resume | /api/growth ──► 对应快照表
  SSE 流式接口 ──► 不写库

删除路径：
  删除用户（当前无 HTTP 接口，仅 DB 层） ──► 经历表 CASCADE 清空；快照表 user_id 置 NULL

更新路径：
  经历表仅"整组替换"，无单条增删改；快照表不可变（append-only）
```

无定时清理任务（`规划/待实现`）。

## 6. 会话与事务约定

1. 会话由 `get_db()` 依赖注入，**请求结束自动关闭**；禁止在请求外持有 Session。
2. 写操作统一在 Service 层提交；`SQLAlchemyError` 时 `rollback()` 后重抛（参考 `UserService._commit_and_refresh`）。
3. 查询聚合根时使用 `selectinload` 预加载四组经历，避免 N+1（参考 `UserService._eager_load_options`）。
4. Engine 参数：`pool_pre_ping=True`、`pool_recycle=3600`；MySQL 额外 `pool_size`（默认 5/20 按环境）、`max_overflow=2×pool_size`；SQLite `check_same_thread=False`（内存库用 `StaticPool`）。

## 8. 表结构变更流程（无迁移工具期间）

1. 修改 `app/models/*.py`（新表记得在 `app/models/__init__.py` 导出注册，否则 `create_all` 不会建表）。
2. 若只**新增表**：直接 `python init_db.py`。
3. 若**修改已有表**：`create_all` 不会变更已存在的表，必须删库重建：
   ```bash
   # 开发环境（SQLite）
   rm ai_job_analysis.db && python init_db.py
   ```
   如需保留数据，先手工导出（`规划/待实现` Alembic 后不再需要）。
4. 同步更新本文档对应表定义 + [02-API接口文档](./02-API接口文档.md) 受影响字段。
5. 回归：`python -m unittest tests.test_user_api -v` + `python test_job_match.py`。

## 10. 数据安全与备份

### 10.1 数据敏感度分级

| 数据 | 敏感级别 | 说明 |
|------|---------|------|
| 学生经历（技能/项目/竞赛/实习）、简历原文 | 高 | 个人敏感信息 |
| AI 分析结果快照（画像/简历优化/成长规划） | 高 | 含个人能力评价 |
| 岗位匹配记录 | 中 | 含技能自评 |

### 10.2 访问控制现状与规划

- **现状**：无用户认证，接口可按任意 `user_id` 读写（仅限内网开发/演示，见 [01 第 13 章](./01-项目开发说明书.md)）；
- **规划/待实现**：JWT 认证 + 数据归属校验——用户只能读写自己的数据（简历/经历/历史记录）；上线前必须完成（见 [开发文档 第 7 章](./开发文档.md)）。

### 10.3 备份策略

| 环境 | 方式 | 频率建议 |
|------|------|---------|
| 开发（SQLite） | 直接复制 `ai_job_analysis.db` 文件（服务停止时） | 重大改表前 |
| 生产（MySQL，规划） | `mysqldump --single-transaction` 全量导出 | 每日定时（见 [06 第 9.3 节](./06-部署说明.md)） |

- 备份文件与数据库同密级管理，不得放入公开目录或提交入库；
- 演示/共享数据导出前先脱敏（姓名/联系方式/简历原文）。
