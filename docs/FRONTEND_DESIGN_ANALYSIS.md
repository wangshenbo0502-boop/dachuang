# 前端设计分析

## 1. 当前页面与信息架构

当前前端采用 Vue 3 单页应用，包含登录、就业能力概览、就业档案、AI 就业画像、岗位匹配、岗位详情、简历优化、成长规划、就业资源、分析记录和系统设置。登录后使用固定左侧导航与顶部栏，主内容区按路由切换。

业务链路完整，页面均通过现有 API 获取真实数据，AI 分析、简历优化和成长规划还接入了 SSE 生成状态。现有信息结构能够支撑比赛演示，不需要改变业务或接口。

## 2. 当前技术与组件结构

- 技术栈：Vue 3、TypeScript、Vite、Pinia、Vue Router。
- UI 框架：Element Plus。
- 数据可视化：ECharts。
- 布局组件：`MainLayout`、`AppSidebar`、`AppHeader`。
- 通用组件：`PageHeader`、`SectionPanel`、`StatCard`、`StateView`。
- 图表组件：`RadarChart`、`BarChart`。
- 状态管理：用户身份、学生档案、侧栏状态分别由 Pinia 管理。

组件边界总体清晰，`SectionPanel` 已经承担基础卡片职责，继续复用比新增一套重复的 BaseCard 更合适。

## 3. 当前样式系统

已有少量 CSS 变量和统一类名，但全部压缩在一个全局文件中。颜色、圆角、阴影和间距在页面类中仍有较多硬编码，Element Plus 默认视觉未完全覆盖，缺少明确的层级、交互状态和移动端细节。

## 4. 主要视觉问题

1. 页面背景、卡片、边框的层级差异较弱，整体偏功能原型。
2. 侧栏品牌识别度不足，导航选中态和底部用户区层级较平。
3. Dashboard 指标、流程入口、AI 画像和成长计划缺少明确的阅读顺序。
4. 卡片、筛选栏、岗位卡、档案编辑区使用了多套相近但不统一的样式。
5. 数字、评分、状态、标签等数据元素的视觉强调不够稳定。
6. 登录页有基本品牌区，但缺少成熟数字化平台的细节与可信感。
7. 小屏下虽然完成单列降级，按钮、筛选和标题区域仍可能拥挤。
8. Loading、Empty、Error 已有组件，但空状态和错误状态的空间、图标和操作样式较弱。

## 5. 主要交互问题

1. 卡片、导航、快捷入口的 hover 与 focus 反馈不一致。
2. 页面切换缺少轻量过渡，内容出现略显生硬。
3. 可点击岗位卡仅依赖鼠标样式，键盘焦点表达不足。
4. AI 流式生成区域和普通结果卡的状态区分不够明显。
5. 表单、弹窗、表格仍保留较强的 Element Plus 默认后台风格。

## 6. 优化方向

- 建立独立 Design Token，统一品牌色、功能色、文字色、间距、圆角、阴影和动效。
- 保留左侧导航与顶部栏，强化品牌区、导航状态和用户身份层级。
- 统一卡片为 12-16px 圆角、轻边框、克制阴影和清晰标题区。
- 重排 Dashboard 首屏层级，增加基于真实用户数据的欢迎与档案进度区。
- 强化评分、进度、技能标签、AI 状态、时间线和岗位卡片的数据表达。
- 系统化覆盖 Element Plus 按钮、输入框、标签、表格、标签页、弹窗等基础控件。
- 使用 160ms-220ms 的轻量过渡，并尊重系统减少动画设置。
- 在 1366、1440、1920 桌面尺寸以及 900、560 以下小屏做稳定降级。

## 7. 页面改造计划

| 页面 | 改造重点 |
| --- | --- |
| 登录 | 品牌识别、表单层级、可信状态、移动端布局 |
| Dashboard | 欢迎区、核心指标、快捷流程、AI 画像、建议和成长路线 |
| 就业档案 | 个人摘要、完成度、标签页、经历卡、编辑弹窗 |
| AI 就业画像 | 生成状态、综合评分、雷达图、优势与短板 |
| 岗位匹配 | 搜索筛选、岗位卡、匹配进度与技能差距 |
| 岗位详情 | 标题区、正文可读性、匹配结果侧栏 |
| 简历优化 | 双栏文档工作区、生成状态、原文与优化结果对比 |
| 成长规划 | 目标摘要、阶段时间线、能力缺口与资源 |
| 就业资源 | 知识库搜索入口、结果层级、来源与相关度 |
| 分析记录 | 信息提示、表格可读性、详情弹窗 |
| 设置 | 用户、偏好、服务状态与安全信息卡 |

本次改造仅调整前端视觉、布局和交互表现，不修改 API、后端、数据库和 RAG 逻辑，也不引入模拟业务数据。
