# 岗位匹配房间改造报告

## 1. GalleryRoom 可复用部分

| 类别 | 内容 |
|------|------|
| **3D 场景** | 阳台地面/栏杆/门槛、晾绳曲线、背景房屋/城市天际线、飞鸟、GalleryClouds、天空球 |
| **动画** | `usePaintMaterial` 画笔入场、`gsap` 卡片展开/收起、`Observer` 滚轮/触摸横向滚动、卡片随风摇摆 |
| **纸张卡片** | `PaperMaterial` 弯曲/双面纹理、`JobCard`（由原 ProjectCard 改造）夹子挂晾交互 |
| **音效** | 城市环境音 `szummiasta.mp3`、点击纸张 `papersound.mp3`（PositionalAudio） |
| **移动端** | `matchMedia('(hover: hover)')` 区分触控/桌面 painted 纹理 |
| **交互机制** | 卡片点击展开、切换选中、滚动锁定、传送跳过画笔、成就 `gallery_inspect`、`showRoom/onReady/isExiting/isWarmup` 契约 |

## 2. 必须移除/停用的旧链路

- `FALLBACK_PROJECTS` 硬编码作品集
- `useGalleryProjects()` 及 Sanity `galleryProject` 查询
- 项目专属纹理（MoneTune/TimberKitty 等 front/painted）
- Tech Stack  logo 预加载与展示
- 卡片背面 `OPEN PROJECT` + `window.open(project.url)`
- ScreenReaderOverlay 中对 `useGalleryProjects` 的依赖

> `useSanityData.js` 本身保留，Studio/About 等仍可使用。

## 3. 三条前端数据流

| 数据流 | 触发 | API | 展示位置 |
|--------|------|-----|----------|
| **岗位列表** | 进入房间 / 搜索 / 筛选 | `GET /api/jobs` → `getJobList` | 3D 晾绳卡片（browse 模式）+ JobMatchPanel 状态 |
| **岗位详情** | 卡片「查看详情」 | `GET /api/jobs/{job_id}` → `getJobDetail` | `GlobalOverlay` layout=`job_detail` |
| **技能匹配** | 「开始匹配」（需 profile.skills） | `POST /api/match` → `startMatch` | 3D 卡片 match 模式 + 详情 Overlay 匹配区块 |

browse 与 match 为独立数据源，通过 `mode` 字段区分，不混用。

## 5. 验收标准与风险

**验收标准**

- 房间内无旧作品集名称、Sanity 数据、外部链接
- 可浏览/搜索/分类筛选后端岗位
- 可查看岗位详情（Markdown 轻量文本化，无 dangerouslySetInnerHTML）
- 有技能档案时可产生真实匹配结果并区分 browse/match
- 无档案/无技能/加载/空结果/接口失败不崩溃
- 就业画像、联系我们房间不受影响；`npm run build` 通过

**风险点**

- 后端未启动时列表/详情/匹配均失败 → 需友好错误提示
- 岗位 `job_id` 含中文 → 已用 `encodeURIComponent`
- 卡片数量随 API 变化 → 动态 CARD_COUNT，空列表显示占位
- match 字段可选 → Overlay 与卡片需优雅降级
