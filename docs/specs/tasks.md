## 执行规则

1. 只有规范批准后才能开始第一个未完成任务。
2. 严格从上到下执行；每个任务完成并验证后才标记完成。
3. 若数据库或 AI 输入契约需要改变，先更新设计和需求规范。

## 阶段 1：基础设施

- [x] **T-001:** 实现数据库配置、SQLAlchemy Base、Session 依赖、统一响应和业务异常，并提供 `.env.example`。
  - 📁 涉及文件：`backend/app/database/connection.py`、`backend/app/database/session.py`、`backend/app/utils/`、`backend/.env.example`、`backend/main.py`
  - ✅ 验证标准：配置可从环境变量加载；缺失资源和业务错误遵循统一响应格式；不泄露敏感配置。

  - 🔗 依赖：无

## 阶段 2：数据模型与资料接口

- [x] **T-002:** 实现用户、技能和项目经历 ORM 模型及 Pydantic Schema。
  - 📁 涉及文件：`backend/app/models/user.py`、`backend/app/models/__init__.py`、`backend/app/schemas/user.py`
  - ✅ 验证标准：模型关系、JSON 技术栈、枚举技能等级和必填字段均通过 Schema 校验。
  - ⏱️ 预估工程量：2-3 小时
  - 🔗 依赖：T-001

- [x] **T-003:** 实现 `UserService` 的创建、读取、更新、技能替换、项目替换和上下文聚合。
  - 📁 涉及文件：`backend/app/services/user_service.py`
  - ✅ 验证标准：列表替换为单事务；不存在用户抛出资源不存在异常；上下文不依赖 AI 模块。
  - ⏱️ 预估工程量：3-4 小时
  - 🔗 依赖：T-002

- [x] **T-004:** 实现并注册 `/api/users` 资料接口。
  - 📁 涉及文件：`backend/app/api/user.py`、`backend/main.py`
  - ✅ 验证标准：六个已定义端点符合统一响应格式和 Schema 契约；API 层只调用 Service。
  - ⏱️ 预估工程量：2-3 小时
  - 🔗 依赖：T-003

## 阶段 3：验证与协作交接

- [x] **T-005:** 为用户资料 API 补充隔离数据库自动化测试。
  - 📁 涉及文件：`backend/tests/test_user_api.py`、相关测试配置文件
  - ✅ 验证标准：覆盖创建、读取、更新、技能替换、项目替换、上下文、校验失败与资源不存在。
  - ⏱️ 预估工程量：2-3 小时
  - 🔗 依赖：T-004

- [x] **T-006:** 发布 AI 成员交接契约和联调样例。
  - 📁 涉及文件：`docs/specs/ai_handover.md`、`backend/tests/fixtures/`（如需）
  - ✅ 验证标准：另一位成员可仅使用 `GET /api/users/{user_id}/context` 的示例响应开发其 Service；契约包含字段说明和错误处理规则。
  - ⏱️ 预估工程量：1 小时
  - 🔗 依赖：T-005
