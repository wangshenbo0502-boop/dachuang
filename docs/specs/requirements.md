# 需求规范：学生资料与数据持久化基础

> **来源设计：** `docs/specs/design.md`
> **版本：** v1.0
> **状态：** 已批准
> **最后更新：** 2026-07-23

## 1. 概述

本规范从已确定的 FastAPI 数据层设计派生，定义首版 Demo 所需的学生资料录入和结构化数据服务。完成后，前端可以保存学生资料，AI 业务服务可以使用稳定的用户上下文进行后续分析。

## 2. 功能需求与验收标准

### REQ-001: 数据库与应用基础

**作为** 后端开发者，**我希望** 应用从环境变量连接数据库并提供统一错误响应，**以便** 服务可在不同机器安全启动。

#### 验收标准

- **AC-001.1:** GIVEN 已设置有效 `DATABASE_URL`，WHEN 服务启动，THEN SQLAlchemy 能创建会话依赖并访问数据库。
- **AC-001.2:** GIVEN 数据库配置缺失或无效，WHEN 应用尝试使用数据库，THEN 客户端获得可理解的统一错误，不含连接密码。

### REQ-002: 学生基本资料管理

**作为** 学生，**我希望** 创建、读取和更新基本资料，**以便** 系统能识别我的教育背景和个人目标。

#### 验收标准

- **AC-002.1:** GIVEN 合法的姓名、学校、专业和年级，WHEN 调用创建接口，THEN 返回新 `user_id` 和保存后的资料。
- **AC-002.2:** GIVEN 存在的 `user_id`，WHEN 获取或更新资料，THEN 返回最新资料且更新时间被更新。
- **AC-002.3:** GIVEN 不存在的 `user_id`，WHEN 调用任何用户资料接口，THEN 返回 `code=3001` 的统一资源不存在错误。

### REQ-003: 技能和项目经历管理

**作为** 学生，**我希望** 保存完整的技能和项目经历列表，**以便** AI 能正确理解我的技术积累。

#### 验收标准

- **AC-003.1:** GIVEN 存在的用户和合法技能列表，WHEN 提交技能列表，THEN 历史技能被替换并返回新列表。
- **AC-003.2:** GIVEN 存在的用户和合法项目列表，WHEN 提交项目列表，THEN 项目名称、职责、描述和技术栈均被保存。
- **AC-003.3:** GIVEN 任一技能等级不在允许集合中，WHEN 提交列表，THEN Pydantic 返回参数校验错误，且数据库数据不变。

### REQ-004: AI 可消费的用户上下文

**作为** AI 业务服务，**我希望** 通过一个接口获得统一的学生上下文，**以便** 无需关心数据库表和 ORM 查询细节。

#### 验收标准

- **AC-004.1:** GIVEN 存在的用户、技能和项目，WHEN 获取 `/context`，THEN 返回资料、技能数组和项目数组。
- **AC-004.2:** GIVEN 后续 AI 服务只调用 `UserService` 或 `/context` 契约，WHEN 数据库内部字段调整，THEN AI 输入的公开字段保持兼容。

## 3. 非功能性需求

| ID | 类别 | 描述 | 来源设计约束 |
|:---|:---|:---|:---|
| NFR-001 | 安全 | 不得在源码、接口响应或日志中暴露数据库密码和 API Key | 环境变量与统一异常 |
| NFR-002 | 一致性 | 替换技能或项目列表必须在单一事务中完成 | Service 层事务控制 |
| NFR-003 | 可维护性 | 所有 API、Service、Model 和 Schema 遵守既有分层和中文文件头规范 | 项目开发规范 |
| NFR-004 | 可测试性 | 核心接口应具备自动化 API 测试，可在隔离测试数据库执行 | 验证策略 |

## 5. 约束、假设与超出范围

### 约束

- 延续 MySQL、SQLAlchemy 2.0、Pydantic v2 与 FastAPI 的现有技术栈。
- API 前缀采用 `/api/users`，与前端 `/api` 基础地址一致。

### 假设

- 未实现登录前，由前端保存创建接口返回的 `user_id`。
- 数据库初始化由开发环境在启动前完成；迁移工具可在后续任务中引入。

### 超出范围

- 认证、权限、删除账号、文件上传、简历文件解析。
- DeepSeek、Prompt、岗位与成长规划 AI 业务实现。
