# IT 求职工作台视觉重构需求

> 版本：v1.0
> 状态：已批准，实施中
> 日期：2026-10-12
> 工作流：Feature / Requirements-First

## 1. 目标与产品定位

面向准备进入 IT 行业的学生，把现有前端重构为清晰、精致、可信的求职工作台。用户应能快速找到目标岗位、理解自己的能力差距、整理简历并继续成长任务。质量来自排版、内容组织、真实数据和交互细节。

## 2. 范围与假设

- 已确认范围：用户选择仅重构 `frontend` 用户端；独立 `admin-frontend` 管理端不在本次范围内。
- 沿现有 `index.html → main.ts → App.vue/router → MainLayout.vue → views` 改造。
- 首要页面：工作台、个人档案、就业画像、岗位列表与详情、求职教练、简历、成长规划、登录/注册/找回密码。
- 配套页面：就业资源、分析记录、设置、投递记录、招聘岗位、站内投递；统一继承设计语言并处理版式冲突。
- 同一前端中的招聘者页面继承共用外壳和控件风格，保留其独立导航与流程。
- 当前工作区存在未提交的前端改动；以现有工作文件为基础，禁止整体回退或覆盖为仓库旧版。
- 采用现有 Vue 3、TypeScript、SCSS、Element Plus、ECharts；不新增运行时依赖。
- 本轮保持现有品牌名称、接口、数据字段、角色、会话存储和功能语义。重构范围是呈现层。

## 3. 用户故事与验收标准

### US-001：登录后知道下一步做什么

作为求职学生，我希望首页突出与我有关的下一步，以便继续准备而不是阅读一整屏指标。

- GIVEN 当前档案和最近分析数据，WHEN 打开工作台，THEN 主要区域呈现现有数据支持的下一步行动，以及对应的档案/画像/简历/成长入口。
- GIVEN 缺少数据或接口失败，WHEN 打开页面，THEN 显示真实空状态或错误与重试入口，不显示伪造分数、岗位数或完成记录。
- GIVEN 岗位行业数据，WHEN 查看市场信息，THEN 保留现有筛选和技能到岗位的关联，并标明样本和来源。

### US-002：在不同工具之间保持连续感

作为学生，我希望页面共享导航、标题和控件习惯，以便切换任务时无需重新学习。

- GIVEN 同一账户，WHEN 在档案、岗位、教练、简历、成长页面切换，THEN 导航选中态、标题层级、操作栏、表单和状态提示保持一致。
- GIVEN 岗位匹配结果，WHEN 浏览列表及详情，THEN 标题、匹配依据、技能要求和操作具有明确优先级，长内容不会挤出布局。
- GIVEN 简历内容，WHEN 进入简历页面，THEN 编辑区与文档预览有清晰区分，导出等既有操作继续使用现有处理函数。
- GIVEN 对话，WHEN 使用求职教练，THEN 消息、回复状态、资料草稿和输入框可辨识，既有流式回复和会话切换保持可用。

### US-003：小屏和键盘也能完成任务

- GIVEN 390px 宽屏幕，WHEN 打开上述主要页面，THEN 导航可开关，主内容无横向页面滚动，主要操作可见；复杂表格允许容器内滚动。
- GIVEN 键盘操作，WHEN 聚焦导航、按钮、表单，THEN 焦点可见，图标按钮保留可理解的名称。
- GIVEN 系统减少动画偏好，WHEN 页面切换或展开内容，THEN 尊重 `prefers-reduced-motion`。

## 4. 品质要求

- 正文通常为 14–16px，正文与说明保持可读对比度；关键操作目标高度至少 40px。
- 颜色、字体、间距、圆角和控件状态由共用 token 驱动；首页不再另造一套应用外壳风格。
- 主要操作每个任务区域通常只设置一个；次要操作按文字或低强调按钮处理。
- loading、empty、error、success、disabled 状态沿现有数据状态清晰表达。
- 不以连续装饰动画、复杂纹理或无信息价值的大图增加页面负担。

## 5. 范围外

后端、数据库、认证/授权实现、API 契约、AI 答案质量、自动投递、发布上线、新业务功能、独立管理端（若用户未选择）。登录页仅修改呈现，不修改身份验证。
